# 选题、原型、规范与架构设计（阶段 0–3）

- 日期：2026-10-23 ～ 2026-10-25 ｜ 工具：Claude Code（桌面端）｜ 模块：需求 / 设计 / 文档

## 任务目标
从课程作业要求出发，确定选题，完成可点击的 UI 原型、开发规范和架构设计，为编码阶段做准备。

## 过程概要

| 阶段 | 我的输入 / 决策 | AI 的产出 | 人工修正（AI 方案被否定或调整的地方） |
|---|---|---|---|
| 选题 | 读取作业 PDF，问哪个题适合放作品集 | 分析三个方向，推荐方向二 · 场景 3（业务智能体） | — |
| 业务场景 | 不想做客服；提出「大模型部署公司的销售系统」 | 先后给出电商售后、店铺运营助手两个方案 | **否定了两次**：①与场景 1 智能客服重叠；②运营助手不贴合我的想法。最终采用我提出的「LLM 部署销售 + 报价 + 提成 + 报销」 |
| 解耦 | 问「我不一定是大模型部署公司，怎么解耦」 | 提出「通用销售流程 + 可插拔行业包」 | — |
| 原型 v1 | 要求先做 UI 原型 | 生成 11 个页面的可点击原型 | 我反馈「不便捷、杂乱」 |
| 原型 v2 | — | 统一按钮、精简布局 | 我反馈控件没做好、AI 页面应是 DeepSeek 式会话；让 AI 先找参考链接 |
| 原型 v3 | 选定 Twenty + shadcn/ui + DeepSeek/Ant Design X | 重做全部页面和控件，AI 页支持流式演示 | 我指出：报销要上传发票、商机侧栏奇怪、**行业包不该由销售决定**、动态可见范围不清 → AI 补充三级数据权限、管理员角色、产品线映射 |
| 响应式 | 要求自适应和侧边栏折叠 | 4 档断点 + 三形态侧边栏 | 我指出横向滑动突兀 → 改为卡片列表 / 隐藏次要列 / 看板单列 |
| 架构 | 要求梳理技术栈和 RAG | 架构设计文档 + 架构图 | — |
| 网关 | 质疑「自研网关容易出 bug」 | AI 改为 LiteLLM Proxy；我追问 New API 和「直接搬代码」 | **AI 的第一版（自研）被否定**；第二版（纯 Proxy）我认为自己的代码太少；最终采用方案 B：自写外壳和兼容层 + LiteLLM 库，并要求支持任意多家模型 |

## 产出
- `prototype/index.html`：可点击原型（含响应式、三种角色、流式演示）
- `docs/开发规范.md`、`docs/架构设计.md`、`docs/架构图.html`
- `AGENTS.md`：给 AI 编程助手的项目规范

## 体会
- AI 给出的第一版方案往往「能用但不贴合」，需要我结合自己的业务理解多轮纠正（选题、行业包归属、网关方案都是人工决策改变了方向）。
- 让 AI 先给出参考产品链接、确认方向后再动手，比直接让它设计效率高。

## 耗时
约 1.5 天（含多轮原型迭代）。
