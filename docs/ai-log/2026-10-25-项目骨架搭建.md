# 项目骨架搭建（阶段 4）

- 日期：2026-10-25 ｜ 工具：Claude Code（主 agent + 3 个并行子 agent）｜ 模块：web / core / gateway / 根目录

## 任务目标
按架构图和开发规范搭建可运行的单仓多服务骨架，并验证 web → core → gateway 的调用链路。

## 做法
1. 主 agent 先写项目规范 `AGENTS.md`（给 AI 编程助手看的硬性规则）、根目录配置（docker-compose、.env.example、.gitignore、README、Nginx）。
2. 三个互不冲突的模块派发给三个子 agent 并行编写，每个只允许改自己的目录：
   - `services/gateway`：注册表 + 兼容层（14 类差异）+ litellm 后端 + 单元/契约测试
   - `services/core`：统一响应、JWT、数据范围、17 张表与迁移、规则计算器、行业包、LangGraph 状态图、SSE、RAG 切块与检索、种子数据
   - `apps/web`：Next.js 15 + shadcn 外壳、业务组件、AI 会话组件、数据层、11 个路由
3. 主 agent 逐个复核子 agent 的结果（重跑 lint 和测试），再做跨模块对齐和联调。

## 发现的问题与修正（校验与兜底）

| 问题 | 原因 | 修正 |
|---|---|---|
| AI 回复里的方案卡片和物料清单在前端会退化成原始 JSON | 三个子 agent 并行开发，core 推送的 `SolutionTier`（`total_price`、`margin_rate`、`items[]`）与前端假设的字段（`price`、`margin`、`spec`）不一致 | 以 core 为准，前端新增 `lib/artifacts.ts` 做结构转换，`ArtifactView` 优先识别 core 原始结构 |
| 前端模型选项 `hunyuan` / `qwen` 在网关里不存在 | 前端没有读网关注册表，凭印象写了别名 | 改为网关的真实别名 `chat-agent`、`hunyuan-turbo`、`deepseek-chat`、`qwen-plus` |
| 前端工具名 `log_followup` / `update_opportunity` 与规范不符 | 子 agent 没对照开发规范 §6.2 | 改为 `add_followup` / `update_opportunity_stage`，补 `pipeline_summary` |
| 示例 JWT 密钥太短，PyJWT 报安全警告 | `.env.example` 写了 `change-me` | 示例改为 32 字节以上的提示值 |
| 网关文档写 `GATEWAY_TIMEOUT_SECONDS=30` 会覆盖 `models.yaml` 的超时 | 两处配置优先级不清 | `.env.example` 留空并注释说明 |
| core 的显存公式与文档不同 | 文档用「隐藏维度」估算 KV Cache，对 GQA 模型会高估约 5 倍 | **采纳 AI 的修正**：改用「KV 头数 × 每头维度」；需同步更新开发规范 §7 |

## 联调验证（本机，无 Docker、无模型 Key）
- web → core：`/dashboard`、`/customers` 返回 200；通过前端 `/api` 代理调用 mock-login 成功。
- core 的 Agent：出方案对话依次产生 `node.start ×8`、`tool.start/end ×5`、`node.retry ×1`（经济版毛利不达标回退）、`artifact ×4`、`interrupt`；确认后 `generate_quote` 因无数据库返回 `tool.error 50001`，符合预期。
- core → gateway：同一个 `X-Request-ID`（itest-hi）出现在网关日志中；网关无可用模型返回 502，core 自动退回模板回复，没有崩溃。
- 测试过程中遇到的环境问题：Windows 下 `localhost` 解析到 IPv6 导致 curl 卡住，改用 `127.0.0.1`；Git Bash 传中文请求体编码出错，改为从 UTF-8 文件发送。

## 还没验证
