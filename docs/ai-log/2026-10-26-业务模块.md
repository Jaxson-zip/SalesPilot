# 业务模块：商机、报价、合同、报销、审批（阶段 5）

- 日期：2026-10-25 ～ 2026-10-26 ｜ 工具：Claude Code（主 agent + 前后端 2 个并行子 agent）｜ 模块：core / web / tests

## 任务目标
按客户模块的写法，补齐商机、报价、合同与提成、报销、审批、工作台、行业包配置、客户跟进的接口和前端页面。

## 做法
1. **先写接口契约** `docs/api/业务模块接口契约.md`（字段、状态值与中文、状态流转、错误码、权限），作为前后端并行开发的唯一依据——吸取上一阶段「方案卡片字段对不上」的教训。
2. **先写验收用例** `tests/e2e/test_business.py`（9 个业务流程），再让子 agent 开发。
3. 后端、前端两个子 agent 并行，分别只改 `services/core`、`apps/web`。中途遇到 API 额度上限，额度恢复后让它们从中断处继续。
4. 主 agent 复核（重跑全部测试）、重建容器、端到端验收、浏览器逐页检查，修复跨模块问题。

## 发现的问题与修正（校验与兜底）

| 问题 | 怎么发现的 | 原因 | 修正 |
|---|---|---|---|
| core 容器显示「健康」，但跑的是旧代码 | 种子脚本打印的仍是旧提示 | 镜像构建时下载依赖网络出错，`docker compose up --build` 失败后继续用了旧镜像 | 单独 `docker compose build` 确认成功后再启动；之后每次都核对输出 |
| 销售新建商机时产品线下拉框不可用 | 前端子 agent 汇报 | 契约把产品线列表定成「仅管理员」，但销售建商机必须选产品线——**契约本身设计错误** | 改为所有角色可读（非管理员只看已启用的），修改仍仅管理员；更新契约、单测、端到端测试 |
| 客户详情页查不到该客户的报价单 | 前端子 agent 汇报 | 报价列表缺少 `customer_id` 筛选参数 | 后端增加参数 + 测试（含「看不到的客户返回空列表」） |
| 工作台动态显示 `create`、`attachment_added` 等英文代码 | 浏览器实测 | 契约没写动作代码清单，前端猜成了 `quote.created` 格式，测试数据也是按猜测写的，所以单元测试全绿 | 按后端实际值（对象类型 + 动作）翻译；契约补上动作代码表；修正测试数据并补回归测试 |
| 报价单「方案」显示 `llm_deploy` | 浏览器实测 | 前端直接显示行业包 id | 新增 `PackName` 组件，名称取自 `/api/packs`（不在前端写死行业信息） |
| 端到端测试产生的数据混进演示数据 | 浏览器看到「e2e 商机」等 | 测试在真实环境新建数据 | 种子脚本新增 `--reset`：清空业务表后重新导入；写入 AGENTS.md |
| Agent 推进商机缺少输单原因时返回 50001 | 后端子 agent 的新测试 | 工具在函数内部构造参数对象，校验错误没被识别为参数错误 | 工具参数直接继承 `StageChange`，解析时就校验，返回 40001 + 回归测试 |

## 契约与实现的调整（已同步到文档）
- 产品线列表改为全员可读；报价列表增加 `customer_id`；列表一律 `{items, total}`；补充 Activity 动作代码表。
- 开发规范：报销状态机去掉 `submitted`；工具清单补 `decide_approval`。

## 体会
- 「先写契约 + 先写验收用例」让前后端并行开发后一次就对上了大部分接口；没写进契约的部分（动作代码、产品线读权限）正好是出问题的地方。
- 单元测试的测试数据如果是「猜」出来的，测试会和错误一起通过——联调和浏览器检查不能省。
