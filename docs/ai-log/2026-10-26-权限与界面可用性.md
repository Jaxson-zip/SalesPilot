# 权限分离、浏览器自动化测试与界面可用性（阶段 6）

- 日期：2026-10-26 ｜ 工具：Claude Code（主 agent + 4 个子 agent，分两轮）｜ 模块：core / web / tests

## 任务目标
用户反馈：①按钮贴边、不协调；②权限分离不明确（例如行业包谁来配置）；③有些按钮显示了却点不了；④不小心点错（如阶段条点了赢单）无法撤销。同时补齐 Playwright 浏览器自动化测试。

## 决策（用户拍板）
| 问题 | 选择 |
|---|---|
| 管理员对业务数据 | **只读**，只负责系统配置 |
| 主管对团队成员的记录 | **查看 + 审批 + 登记回款**，不替销售改商机 / 提交报价或报销 |
| 界面表达 | 无权操作的按钮**隐藏**（不置灰）；导航按角色分组 |

权限矩阵写入 `docs/api/业务模块接口契约.md` §0，作为前后端唯一依据。

## 发现的问题与修正（校验与兜底）

| 问题 | 怎么发现的 | 原因 | 修正 |
|---|---|---|---|
| 管理员能直接改销售的商机 | 工作台动态里出现「周敏（管理员）更新了商机阶段」 | 权限只做了「能看什么」，没做「能改什么」 | 后端集中实现 `ensure_owner` / `ensure_business_writer`，所有写操作复用；返回 40301 并注明 `role_forbidden` / `not_owner` |
| 看板卡片「显示了却点不了」 | Playwright：主管点别人的卡片超时 | 不可拖的卡片外层仍套拖拽组件，带 `role="button" aria-disabled="true"`，里面又套一层按钮；键盘回车无反应，拖动还会选中大片文字 | 不可拖的卡片不包拖拽层；可拖的只保留一层按钮；加 `select-none` |
| 一批「点了没反应」的按钮 | **自写脚本扫描**所有页面里没有点击处理器或永久禁用的按钮 + 代码搜索 | 筛选 / 排序 / 选项菜单项、新建客户、AI 分享 / 上传附件 / 历史会话、行业包「产品目录 / 业务规则 / 知识库」、物料清单导出等只做了样子 | 能做的做成真功能（筛选排序、导出 CSV、新建客户、会话历史、行业包详情），无意义的删除；扫描脚本固化为回归测试 `ui-audit.spec.ts` |
| 误点「赢单」无法撤回 | 用户反馈 | 阶段条和看板一点即生效，赢单是终态 | 可逆操作立即生效 + 8 秒「撤销」；不可逆操作（赢单、报价发送 / 接受 / 拒绝、审批通过、提交报销、登记回款）先确认 |
| 测试时好时坏 | core 测试因开发库里残留的测试数据失败（第二次出现） | core 测试、接口端到端、浏览器测试共用开发库 | core 测试改用独立的 `crm_test` 库，每次运行前自动建库、迁移、重建演示数据 |
| 选择框贴边 | 用户反馈；脚本测距 + 截图 | 下拉菜单视口无内边距、选项贴边；客户组合框显示两个勾选图标；☰ 按钮离屏幕 4px 等 | 逐项修复（详见前端子 agent 汇报） |
| Playwright 浏览器一直装不上 | 安装命令长时间无输出 | 第一个安装进程卡住并占着缓存目录的锁，后续安装都在等 | 结束卡住的进程、删除残留锁；改为可直接调用 Windows 自带 Edge（`PW_CHANNEL=msedge`），免下载 |

## 子 agent 越界的情况（如实记录）
- 前端子 agent 为了看页面，另起了一个开发服务器，弄坏了用户本机 3005 端口 dev server 的 `.next` 缓存，随后**重启了用户的 dev server**。之后的任务里明确禁止子 agent 启动或停止任何开发服务器，构建改用 Docker。
- 前端子 agent 两次用 `prettier --write .` 格式化了不属于它的 e2e 文件（只改格式，未改逻辑）。
- shadcn CLI 静默加入了一个第三方 `cn` 依赖，已移除；`alert-dialog` 组件改为手写。

## 体会
- 「看得见却点不了」靠肉眼很难找全，写一个扫描脚本一次就找出了 10 多处，并且可以固化成回归测试。
- 测试数据隔离要尽早做：共享数据库导致的「时好时坏」会让人怀疑新代码，浪费排查时间。
