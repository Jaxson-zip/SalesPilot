## 发现的问题与修正（校验与兜底）

| 问题 | 怎么发现的 | 原因 | 修正 |
|---|---|---|---|
| **「参考来源」从来没有显示过** | 写《知识库构建说明》时核对「回复带出处」这句话 | 前端有 sources 组件，core 从不推送 sources，架构里的「回答必带出处」只做了一半 | 检索命中时推送并保存到会话历史；补回归测试 |
| PDF 标题和正文粘在一起 | 把提取结果写到文件逐页对照（控制台是 GBK，直接打印是乱码） | 「行尾没有句末标点就合并」把标题和表格行都并进了正文 | 识别标题；只合并长度接近整行宽度的行 |
| 页眉页码没去掉 | 同上 | 文档只有 2 页，最初要求 3 页起判断；pypdf 把「示」「页」提取成康熙部首字符 | 2 页起判断首尾两行；部首字符规范化 |
| 全角标点变半角 | 修上一条后再次对照输出 | AI 第一版对整行做 NFKC | 只规范化部首和兼容汉字区 |
| 章节路径「第一章 > 第二章」 | 同上 | 标题路径按级别下标截断，没有一级标题时出错 | 改为标题栈；补回归测试 |
| Nginx 覆盖了请求 ID | 读配置 | `X-Request-ID $request_id` 总是用 Nginx 生成的 | 客户端带了就透传；去掉造成重复的 `add_header` |
| Nginx 健康检查写成 `/api/../health` | 自查 | AI 想借 core 的 `/health`，路径归一化后其实落到 web | Nginx 自己提供 `/nginx-health` |
| 上一轮提交留下 1 个 import 顺序问题 | 本轮运行 ruff | 上轮最后只跑了测试没跑 lint | 修复；以后提交前固定跑 `ruff check .` |
| Python 脚本写入的 `\n` 变成真换行（第 3 次） | 语法错误 | 命令行 heredoc 的转义处理 | 含转义的内容一律用编辑工具写 |
