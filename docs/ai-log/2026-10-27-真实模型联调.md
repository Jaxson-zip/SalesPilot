# 接入真实模型（DeepSeek）联调与模型选择（阶段 11）

- 日期：2026-10-27 ｜ 工具：Claude Code（单 agent）｜ 模块：gateway / core / web

## 任务目标
用户在 `.env` 里配置了 API Key，反馈「好像没有模型选择的选项」。

## 做了什么

| 部分 | 内容 |
|---|---|
| Key 没生效 | `.env` 的修改时间（20:01）晚于容器启动时间（19:59），容器里 Key 为空；重建网关和 core 后 DeepSeek 可用。只配了 DeepSeek，混元、通义为空 |
| 模型选择 | 选择器一直在 AI 工作台输入框底部，但只写「自动（失败切换）」，看不出是选模型，下拉里还露出内部分组 `chat-default`。改为「模型 · 自动 · 当前 DeepSeek」；下拉分「自动切换 / 指定模型」两组；未配 Key 的标「未配置 Key」不可选；只显示对话默认分组 |
| 工具调用全部失败 | 联调时发现：纯文本对话正常，带 tools 的请求一律 502，AI 悄悄退回规则模式。直接调网关拿到上游错误 `No module named 'mcp'`——litellm 1.106.4 遇到 tools 会导入 MCP 模块，`mcp` 只在可选依赖里。依赖改为 `litellm[mcp]` |
| 构建超时 | 镜像构建下载 PyPI 两次超时（Docker Desktop 走代理）；Dockerfile 用 ARG 放宽 `UV_HTTP_TIMEOUT`、降低并发，只在构建时生效 |
| 契约测试 | 用真实 DeepSeek 跑 10 个契约用例：9 通过；「上下文超长」上游接受了 25.6 万 token 未报错，改为上游接受时跳过并写明实测 token 数；`max_context` 64000 → 128000；重新生成兼容矩阵 |
| 表格渲染 | 真实模型爱用 Markdown 表格，react-markdown 默认不支持，整张表挤成一行；加 remark-gfm，表格外层可横向滚动 |
| 制度问答 | 没配 Embedding（混元）时知识库不可用，`search_policy` 把「502」交给模型，AI 对销售说「网关错误」。改为返回 `rules.yaml` 的标准并标明「暂无条款出处」 |
| 提示词 | 回复里不写英文阶段代码和 id，金额写「元」不写「分」，不提网关等技术细节 |

## 发现的问题与修正（校验与兜底）

| 问题 | 怎么发现的 | 原因 | 修正 |
|---|---|---|---|
| 配了 Key 前端仍是规则模式 | 对比容器启动时间与 `.env` 修改时间 | Compose 只在创建容器时读 `env_file` | 重建容器；写进测试报告的排查表 |
| 工具调用 502 | 网关日志 `attempts: deepseek-chat 502`，core 日志 `llm classify failed, fallback` | 缺 `mcp` 包 | `litellm[mcp]`；新增用例走真实 litellm + `mock_response`，先确认卸掉 mcp 时失败、装上后通过 |
| 回归测试一开始不会运行 | 新增 `.test.tsx` 后用例数没变 | Vitest 只匹配 `*.test.ts`，且没开自动 JSX | 加 `*.test.tsx` 和 `esbuild.jsx = automatic`；临时去掉 remark-gfm 确认用例会失败 |
| 浏览器用例依赖本机环境 | 配了 Key 后「规则模式提示」用例必然失败 | 用例假设「没有 Key」 | 用 `page.route` 固定 `/api/agent/models` 的返回，有 / 无模型两种情况都测 |

## 遗留
- 混元、通义 Key 未配置：Embedding（知识库入库、评测）仍不可用；要启用制度检索，填 `HUNYUAN_API_KEY`，或把 `embed` 分组换成通义 Embedding 并填 `DASHSCOPE_API_KEY`。

## 追加：写操作的真实模型验证

用户重置演示数据后，用 DeepSeek 逐个验证推进商机、安排下一步、主管审批，并点「确认执行」后查库核对。

| 场景 | 第一次的问题 | 修正后 |
|---|---|---|
| 推进商机 | 模型没调工具，只用文字问「确认要推进吗」，用户要确认两次 | 提示词要求信息齐全时直接调用工具；直接弹卡片，确认后阶段为商务谈判 |
| 安排下一步 | 任务创建成功，但「已创建提醒」显示在确认卡片上面 | 确认后的续写存为 `afterText`，显示在卡片下面 |
| 主管审批 | 回复里说「我需要先拿到 approval_id」；审批后侧栏「审批 2」不变 | 提示词禁止字段名和内部步骤；确认过写操作的回合结束后刷新全部业务数据 |

结果：前端单元 209 passed（新增确认前后文字分段 2 个）、浏览器 38 passed、接口端到端 23 passed、core 390 passed。
