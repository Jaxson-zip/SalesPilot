# 软件外包行业包：模糊需求分步确认、个人全栈报价、AI 评估（阶段 15）

- 日期：2026-10-28 ～ 10-29 ｜ 工具：Claude Code（单 agent）｜ 模块：core / gateway / web / docs

## 任务目标
用户：「有种场景客户需求很模糊，要一步步确认，这种现在的 CRM 系统有做到吗？还有如果是一人全栈开发又是什么报价的，成本如何算呢，token 费用等。」

原有两个行业包（大模型部署、IT 办公）都是「需求齐了直接出三档报价」，没有中间确认；成本只有硬件和人天。于是新增软件外包行业包，并补一套评估脚本证明 AI 拆需求是可靠的。

## 做了什么

| 部分 | 内容 |
|---|---|
| 行业包 | AI 把客户描述拆成功能模块（优先用模块库，复杂度简单 / 中等 / 复杂），人天和价格由配置器按模块库计算；三档：经济版只含客户提到的、标准版补齐、高配版加测试与运维 |
| 分三步确认 | ① 粗估区间（只算客户提到的 ～ 全部模块）② 需求卡片：销售和客户一起增删模块、改复杂度、标二期、选交付端 ③ 确认后才出正式三档报价；需求保存在商机上（迁移 0017），侧栏显示，确认记入动态 |
| 个人全栈 | 交付方式选「个人全栈」时角色统一为全栈人天、去掉项目管理，AI 编码工具提效系数 0.7；工期按一人折算 |
| 成本拆分 | 人工、AI 编码工具（每人天 ¥30）、第三方代采（云服务器、域名证书、小程序认证、苹果开发者，按成本价）、服务；有 AI 功能时估算上线后每月模型调用费（按 AI 用量规则的单价，客户另付） |
| 预算判断 | 客户预算低于标准版时推荐经济版；低于经济版时明确提示「建议砍功能或分期」 |
| 报价单打印 | 有已确认需求时显示「项目范围」：交付端、交付方式、本期不含的功能 |
| 评估 | `evals/`：23 条人工标注用例（含 3 条模糊需求），大模型与规则兜底对比；检查关键模块召回、二期识别、追问、数值抽取、报价自洽、解释中的数字能否溯源 |

## 发现的问题与修正（校验与兜底）

| 问题 | 怎么发现的 | 原因 | 修正 |
|---|---|---|---|
| 第一次评估「大模型」列大部分其实是规则结果 | 看网关日志，从第 6 条起全部报错 | 线上抽取失败会静默退回规则，评估脚本沿用了这个函数 | 评估自己调用模型，失败单独记「模型调用失败」不计入指标；连续 3 次失败停止 |
| DeepSeek 余额不足被报成「请求参数错误」 | 直接调 DeepSeek 拿到 `402 Insufficient Balance` | 网关把 LiteLLM 的 BadRequestError 一律归为 400 | 402 / Arrearage 归类为 `insufficient_balance`，允许切到下一个模型 |
| 评估把「比经济版多约 1.16 万」标成来源不明 | 逐条核对 | 只对照草稿里的原数字 | 新增「推算」类：两个金额之差、比例取整 |
| 从历史记录重新打开会话后，报价不再关联商机 | 用户反馈 | 打开历史会话时没有恢复 opportunity_id；后续消息还会把它覆盖成空 | 历史接口返回会话的 opportunity_id，前端恢复；后端只在传入时才更新 |
| 改提示词修一条，另一条固定失败 | 全量重跑评估 | 新规则提到 web，模型在没说端时多加了网站 | 补充「没说端时只选一个客户端」；以后改提示词必须全量重跑 |
| 方案说明里出现「结合并发」 | 读评估输出 | 提示词是为大模型部署包写的 | 改为「结合客户的需求和预算」 |
| 需求卡片在手机上模块名被挤成一个字 | 390 宽截图 | 名称和两个分段按钮挤在一行 | 窄屏名称独占一行 |
| 清理测试数据时外键报错 | 接口测试 | 新增的会话关联了商机 | 清理时先删会话 |
| 修改文件「成功」但内容没变（3 次） | 测试失败才发现 | 工作区是 CRLF，脚本按 LF 匹配，没匹配上也没报错 | 脚本先统一换行再匹配，找不到就报错 |
| 跑 e2e 会把企业微信推送重新打开 | 跑之前读用例 | v9 用例保存配置时 `webhook_url` 为空会回落到环境变量 | 跑 e2e 前先注释掉 `.env` 里的地址，跑完恢复并核对 |

## 补充：提交前自动评估

用户：「把评估接成提交前自动跑」。`infra/git-hooks/pre-commit`：提交里改到 `app/packs`、`app/agent`、`app/llm`、`evals` 时，在本机跑工作区代码的评估并与 `evals/baseline.json` 对比，基线里通过的用例这次没过就拦下提交。

- 模型输出有随机性：失败的用例复跑 2 次，3 次里失败 2 次以上才算回归；模型调不通只警告不拦（网络、余额不该挡住提交）。
- 在基线里临时加一条注定失败的用例，确认退出码为 1、提交被拦下。
- AI 第一次验证时把管道里 `tail` 的退出码当成了脚本的，显示 0；单独取退出码才确认是 1。

## 补充：图片 OCR、没有 SOP 的需求

用户：「客户给了 30 张图片，需要做一个结构化工作流，要用大模型 OCR 识别，没有 SOP 文档，AI 会怎么拆？」实测拆解和追问都对，但报价有三处缺口，按用户确认改了：

| 缺口 | 修改 |
|---|---|
| 「没有 SOP」没有变成工作量 | 需求新增 `no_sop`；为真时三档都加「业务调研与 SOP 梳理」（默认 5 人天，产品经理单价，不按研发比例、不打 AI 折扣） |
| OCR 月费按聊天调用估（¥105/月），与张数无关 | 模块库新增 `ocr`（与对话类 `ai` 分开）；需求新增 `ocr_monthly_pages`；月费 = 张数 × 每张费用，没说量按默认 3000 张并写明；样例张数不算业务量 |
| 没建议先做验证 | 有 `ocr` 模块时推荐档附「先用样例做识别验证（8 人天，单独报价）」，需求卡片显示同样的提醒 |

需求卡片新增「流程文档：客户已有 / 没有，需要梳理」和「每月识别量」，销售核对时直接改。

| 问题 | 怎么发现的 | 原因 | 修正 |
|---|---|---|---|
| 简短的 OCR 描述 8 次里约 1 次被追问「要做哪些端」 | 单条用例重复跑 | 以为是没返回结果，直接打印 10 次模型输出才看清：模块都拆了，只是漏填交付端；改提示词压不住 | 配置器新增 `fill_defaults`：合并上一轮草稿、规则、模型结果之后，有功能没有端时默认网站，卡片上可改。放在合并之后，避免多轮对话里覆盖上一轮的端（AI 第一版放在规则草稿里，会覆盖，自查发现后改掉） |
| 物联网用例改完后 3 次失败 2 次 | 全量评估 | 模型把「超标短信报警」归成自定义模块，不是模块库的消息通知；功能拆对了，是标注写死了 key | 标注放宽为「message 或名称含 报警 / 短信」 |

结果：评估 26 条，大模型 26/26、规则兜底 12/26；core 505、web 单元 237、需求卡片 e2e 2 个通过。知识库里的报价说明更新了，需要 DashScope 网络恢复后重新入库才能被检索到。
