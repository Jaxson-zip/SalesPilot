# 销售增强：材料消化、数据安全、赢单辅导、战卡、日报、推送、情报、AI 用量（阶段 14）

- 日期：2026-10-28 ｜ 工具：Claude Code（单 agent）｜ 模块：core / web / docs

## 任务目标
用户在审查 v7、v8 后要求把「真实销售团队每天会用到、但 CRM 常常缺的」能力补上。按对销售价值排序，依次做了 8 个功能，每个功能单独提交、带接口测试和浏览器测试。

## 做了什么

| 功能 | 内容 | 迁移 |
|---|---|---|
| 一手材料消化 | 上传纪要 / 聊天记录 / Word / PDF / 名片图片，AI 整理成「跟进 + 联系人 + 下一步」，一张确认卡片同一事务写入；原文用 `<material>` 包裹，只作数据不执行其中指令；图片走 qwen-vl | — |
| 数据安全 | 操作日志（中间件记网页写请求含失败原因、AI 写操作、登录、查看电话、导出）；联系人电话脱敏，查看留痕且每天限次；导出前登记，销售不能导出客户名单 | 0010 |
| MEDDIC 赢单辅导 | 商机赢单要素逐项标注与证据；按阶段提示应确认而未确认的要素（只提示不拦截）；AI 评估一键采纳 | 0011 |
| 竞品战卡 | 管理员维护；销售按客户原话搜索；商机标注竞品后直接看应对话术；战绩按商机输赢回流 | 0012 |
| 日报 | 草稿的事实来自操作日志、跟进、任务，AI 只组织语言；主管看团队提交情况和近 7 天汇总 | 0013 |
| 企业微信推送 | 待审批提醒、赢单喜报、日报汇总与提醒；只接受企业微信官方域名，网页只显示脱敏 key；事务提交后才发送 | 0014 |
| 外部情报 | `IntelProvider` 接入层，内置演示数据源（按客户名稳定生成，页面明确标注「演示数据」）；相关招标、负面舆情生成提示 | — |
| AI 用量 | 回调记录每次模型调用的 token（含流式），按人员 / 功能 / 模型统计，月度预算提醒 | 0015 |

另外修了审查 v8 发现的问题：全局搜索一打开就白屏（缺 cmdk 根节点）、审批列表不突出金额、业务规则套了多余侧栏；以及看板标赢单不能按报价成交、「出方案」不带客户上下文、看板卡片不显示赢单要素和竞品。

## 发现的问题与修正（校验与兜底）

| 问题 | 怎么发现的 | 原因 | 修正 |
|---|---|---|---|
| 测试会往真实企业微信群发消息 | 写推送功能时自查 | 赢单、审批等测试会触发推送 | `tests/conftest.py` 全局拦截真实发送；e2e 配置用例保存时关闭推送 |
| 推送在事务回滚后仍然发出 | 代码审查 | 在业务函数里直接发送 | 改为注册在事务提交之后，回滚不发 |
| 材料里写「忽略以上指令」会被模型执行 | 设计时考虑注入 | 原文直接拼进提示词 | 用 `<material>` 包裹并在系统提示中声明只作数据；写操作仍需人工确认 |
| 日报草稿编出没做过的拜访 | 真实模型实测 | 让模型自己回忆当天工作 | 事实只从操作日志、跟进、任务取，模型只负责组织语言 |
| 外部情报像真数据，容易误导 | 自查 | 演示数据没有标注 | 页面和 AI 回答都必须说明是演示数据 |
| 战卡页用了紫、绿、琥珀多种标题色 | 用户截图反馈 | 新页面没有沿用列表页样式 | 改成与操作日志一致的工具栏 + 行列表，紫色只留给 AI |
| 看板标赢单不生成合同 | 用户反馈 | 只有「客户接受报价」走成交逻辑 | 赢单弹窗可选报价，走同一套成交逻辑生成合同、回款计划和提成 |
