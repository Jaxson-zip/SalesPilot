## 补充：三档方案可另选、开票跟踪（B-02）

用户：「把开票跟踪也做了吧 然后就是选择方案 好像现在ai方案那个点击不了 只能默认他说的 那我想看看别的方案不行嘛」

**三档另选**：原来三档卡片只能看，确认时后端固定按推荐档生成报价单。改为卡片可点选（键盘也可以），物料清单和确认卡跟着切换；确认时 `/resume` 带上 `tier`，确认节点记下 `chosen_tier`，生成报价单按所选档位。只对「生成报价单」的确认有效，档位不存在返回 40001。

**开票跟踪**：按回款计划的每一期跟踪（ToB 客户通常见票付款）。销售申请（专票 / 普票，备注抬头税号）→ 主管收到通知后登记发票号码和日期 → 已开票但没收齐的金额和天数在回款计划、合同列表里单独提示；主管可以作废。调整回款计划时开票信息按期次带过去，已开票的期次不能删、不能改金额。演示数据里悦海合同第 2 期已开票未回款、第 3 期已申请待开票（`seed --reset` 后可见）。

| 问题 | 怎么发现的 | 修正 |
|---|---|---|
| 选档测试取到的不是最终方案 | 单元测试失败 | 这条用例会触发一次毛利回退，方案卡片推送两次，以最后一次为准 |
| 侧栏里发票做成一列太挤：期次名、日期换行，两列金额挤在一起 | 截图检查 | 发票信息放到每期下面单独一行，期次、金额、日期不换行；统计卡改两列 |
| 回款计划表格行数变了，原有浏览器用例失败 | 跑相关浏览器测试 | 用例改为表头 + 每期两行 |
| 开票浏览器用例提交后显示旧数据 | 用例失败截图 | 模拟接口在开票后再拉取时返回新数据（页面本身会在成功后重新拉取） |

测试：core 524 通过；前端单元 242；浏览器相关 10 个文件 41 条通过（含新增选档 1 条、开票 2 条；开票用例模拟回款计划接口，不改真实合同）。

## 补充：按人一键交接（M-01）

用户：「把按人一键交接也做了吧」

原来只能在客户列表勾选后批量转移，离职交接要一页页勾。新增主管专用的「按人交接」：选交接人后先预览名下客户、进行中的商机、未成交报价、未完成任务、回款中的合同数量，再选接手人确认。复用原有的按客户转移逻辑（联系人、跟进、待审批报价一起转），另外把回款中的合同和回款计划交给接手人，这样后续回款、申请开票有人负责；提成按人记录，仍归原负责人。

| 问题 | 怎么发现的 | 修正 |
|---|---|---|
| 接口测试如果拿演示账号做交接，会把演示数据整体转走、影响其他用例 | 写测试前检查 | 测试里临时建一名销售和他的客户、任务、合同，跑完全部删除 |
| 对话框文案用了「他名下」 | 自查 | 改成中性写法「这位成员名下」 |

测试：core 526 通过（新增预览 + 交接、权限和错误码 2 条）；前端单元 243；浏览器新增 2 条（交接流程模拟接口，不改真实数据）及客户、权限相关用例共 13 条通过。

## 补充：登录页、演示账户与访问口令

用户：「加访问口令吧 加个演示账户吧」

原来没有登录页：打开就以销售身份静默登录，左下角切换角色。公网部署后任何人都能以管理员身份进入。现在：没有登录的访问都会跳到登录页，选演示账户（张晨 销售 / 李薇 主管 / 周敏 管理员，每个写明能做什么）进入，登录后回到原来的页面；服务端设置 `ACCESS_CODE` 后必须先输入口令，口令用常量时间比较，同一 IP 错 10 次锁 10 分钟；已登录用户在左下角切换账户带着当前 token，不用再输口令。退出登录、token 过期都回登录页。

| 问题 | 怎么发现的 | 修正 |
|---|---|---|
| 退出登录后偶尔跳到 `/login?next=/dashboard` | 浏览器用例失败 | 退出时还有请求在途，401 处理又带着当前路径跳了一次；退出改为整页跳转到登录页 |
| 测试助手每次导航都把 token 写回去，退出登录在测试里不生效 | 同上 | 每个 token 只写一次（用 sessionStorage 记住） |
| 登录页默认选中上次账户可能水合不一致 | 自查 | 挂载后再读 localStorage |

测试：core 529（口令 3 条）；浏览器新增登录 3 条（口令场景模拟接口，本地 `.env` 不用配口令）；全部浏览器用例改为经接口拿 token 登录后全量回归。

## 补充：账号体系

用户：「抛开作业需求……以一个真正能用的 crm 系统来说还缺少什么」→ 列出缺口后「按你说的顺序来，先做账号体系」。

原来只有 3 个写死的演示身份，没有密码，token 里的角色签发后就不变。现在：账号密码登录（scrypt 哈希、错误锁定、不暴露账号是否存在）；管理员「成员与团队」页新建成员（生成临时密码只显示一次，首次登录强制改密）、改角色和团队、重置密码、停用 / 启用、新建和改名团队；每个请求按用户 id 查库，停用和改密码立即让旧登录失效，改角色马上生效；停用时名下还有客户就通知主管，点通知直接打开「按人交接」并预选这个人，接手人只能选启用的成员。演示账户保留（`DEMO_LOGIN` 控制），4 个演示用户由迁移补上登录名和初始密码。

| 问题 | 怎么发现的 | 修正 |
|---|---|---|
| 「新人看不到别人的会话」用例用库里不存在的用户签 token，改为查库后 401 | 全量测试 | 这正是想要的行为：用例改为先断言 401，再临时建用户验证 |
| 新建账号后第一次请求可能被缓存成「不存在」 | 同上（先 401 再建用户仍然 401） | 只缓存查到的账号，不缓存「不存在」 |
| 登录页输入后「请输入账号」提示不消失 | 浏览器用例失败截图 | 输入时清掉对应字段的错误 |
| lint 报 233 个错误 | 跑 lint | 是上一轮全量浏览器测试生成的 `playwright-report`（已在 .gitignore），删除后正常 |
| 用例按标签找「密码」找不到 | 用例超时 | 标签带必填星号，改用输入框 id 定位 |

测试：core 537（账号 8 条）；前端单元 246（密码 / 登录名规则 3 条）；浏览器新增登录 6 条（含关闭演示账户、首次登录强制改密）、成员与团队 3 条（新建、停用、交接预选，均模拟接口）。

## 补充：服务端分页

用户：「继续完善服务端分页 向下推进」。

原来客户 / 报价 / 合同 / 报销 / 商机列表都是 `page_size=100` 一次取回，在浏览器里筛选、排序、导出——数据过百后后面的看不到，筛选项也只来自已加载的那一页。改为：列表接口支持多选筛选和排序，另加 facets 接口给出整个范围的筛选项；前端列表 50 条一页带翻页，导出取全部页；看板逐页取全；关联客户下拉改服务端搜索。

| 问题 | 怎么发现的 | 修正 |
|---|---|---|
| 合同「有逾期」原来在 Python 里按回款计划逐期冲抵算出 | 改服务端筛选前读 `payment_plan.allocate` | 等价改写成 SQL：存在已过期的一期，其按期次累计应收 > 已回款；测试对比服务端筛选和列表项 `overdue_amount` 一致 |
| 商机「停滞」依赖配置和最近活动，SQL 不好表达 | 同上 | 看板本来就要全部卡片：逐页取全后仍在前端筛选；列表类页面全部改服务端 |
| 回款计划通知链接 `?plan=` 在已加载的列表里找合同，分页后可能不在第一页 | 改合同页时检查依赖列表数据的地方 | 改为按 id 单独取合同 |
| 多选参数用逗号拼接时，行业名里有逗号会被拆开 | 设计时考虑 | 改用重复参数，单元测试覆盖带逗号的值 |
| 浏览器用例按钮名称写错（「更多选项」实为「选项」） | 用例失败 | 改正 |

测试：core 新增 10 条（每个筛选与「全量后按同样规则过滤」结果一致、翻页不重不漏、排序、筛选项覆盖范围、非法参数 400）；前端单元新增 5 条；浏览器新增 2 条（翻页 / 筛选参数 / 导出取全部页，模拟 120 条数据）。
