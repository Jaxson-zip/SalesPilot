# 上线加固与模型接入

- 日期：2026-10-30 ｜ 工具：Claude Code（单 agent）｜ 模块：core / gateway / web / infra / docs

## 任务目标
1. 用户问「是不是可以上线了」，要求按真实上线标准逐项检查并修复。
2. 用户希望模型厂商的 API Key 不必写在服务器文件里，能在网站上直接编辑。

## 上线检查发现的问题

| 问题 | 怎么发现的 | 怎么改的 |
|---|---|---|
| 登录「错 10 次锁定」按客户端可伪造的 `X-Forwarded-For` 计数，换假 IP 可无限猜密码 | 读登录代码时追来源 IP 的取法；又确认 Next.js 的代理不会追加真实地址 | 默认只认连接对端；放在 nginx 后面时设 `TRUST_PROXY_HEADERS=true`，读 nginx 用 `$remote_addr` 覆盖写入的 `X-Real-IP` |
| nginx 的 `/api` 从来没把来源 IP、请求 ID 转给 core | 改 nginx 配置时想起 nginx 的规则：location 里只要写了 `proxy_set_header`，外层的就全部不继承 | 公共请求头抽成 `snippets/proxy.conf`，每个 location 都 include；两份配置用 `nginx -t` 检查 |
| 默认 `JWT_SECRET` 只打警告照常启动；数据库密码是默认的 `crm`，端口还对所有网卡开放 | 查运行中的容器端口和 `.env`（只比较是否等于默认值，不打印内容） | `DEMO_LOGIN=false` 视为正式模式，默认密钥 / 默认数据库密码直接拒绝启动；新增 `docker-compose.prod.yml` 只开放 nginx |
| 关掉一键登录后，演示管理员仍可用 README 里公开的 `demo2026` 登录 | 对照 README 和登录代码 | 正式模式下演示账号不能用公开初始密码登录 |
| 空库没有办法建第一个管理员 | 想「不导入演示数据怎么开始用」 | `python -m seed.admin <登录名>`：新建管理员或重置已有账号密码（临时密码，首次登录强制改） |
| 没有备份、不会自动重启、日志不限大小 | 逐项过上线清单 | 备份 / 恢复脚本（实测备份后恢复到临时库，核对各表条数一致）；prod 编排加自动重启和日志轮转 |

## 网页管理模型 Key
- 「系统设置 → 模型接入」（只有管理员）：每家厂商一张卡片，显示来源（网页 / .env / 未配置）、是否可用、末 4 位；可以测试连接（不保存），保存后立即生效。
- 存储：用 `JWT_SECRET` 派生的密钥加密（Fernet）存进 `integrations` 表；任何接口都不返回完整 Key，操作日志不记请求体。
- 生效：core 把网页上的 Key 推给网关，网关按新值重新解析 `models.yaml` 并重建 LiteLLM Router，不用重启。网关只放内存，core 每分钟比对版本，网关重启后自动补推。
- 实测：真实环境里「测试当前 Key」调通了 DeepSeek；用假 Key 测试时，厂商的报错里只显示末 4 位。

## 问题与修正（本阶段 AI 自己的错误）
| 问题 | 怎么发现的 | 修正 |
|---|---|---|
| 用 Python 改文件时，Windows 下默认写出 CRLF | `git diff` 提示换行会被替换 | 统一转回 LF，之后写文件都显式 `newline="\n"` |
| 备份脚本在 Git Bash 下把容器内路径 `/data` 改写成 Windows 路径 | 第一次实跑备份就报错 | 脚本里设 `MSYS_NO_PATHCONV=1`（Linux 服务器上无影响） |
| 测试连接的报错带着「litellm.BadRequestError: OpenAIException -」前缀，管理员看不懂 | 真实环境用假 Key 测试 | 去掉前缀，只留厂商给的原因 |
