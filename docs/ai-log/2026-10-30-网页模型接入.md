# 网页模型接入：自定义厂商、地址、协议、默认模型

- 日期：2026-10-30 ｜ 工具：Claude Code（单 agent）｜ 模块：gateway / core / web / docs

## 任务目标
上一版只能在网页上填内置三家的 Key。用户发现填了混元 Key 仍提示 `api_base not configured`，并提出：接口地址、API Key、协议都应该能由管理员在网页上配置；也问 Key 存数据库是否更安全。

## 先修的问题
- 混元的接口地址在用户的 `.env` 里是空的，网页上只能填 Key，所以混元一直不可用。改为 `models.yaml` 支持 `${VAR:-默认值}`，三家写上官方地址，`.env` 不填也能用。

## 方案
| 部分 | 做法 |
|---|---|
| 网关 | 新增 `app/overlay.py`：core 推来的完整配置叠加在 `models.yaml` + `.env` 上重建注册表（内置厂商改 Key / 地址 / 协议，自定义厂商的模型别名为「厂商标识-模型名」，`chat-agent` / `embed` / `rerank` 分组按能力过滤）。测试连接对对话模型额外检测工具调用、流式、流式工具调用、JSON 能力，对 Embedding 返回向量维度 |
| core | `model_config_service`：加密存库（`MODEL_KEYS_SECRET`，没设置时退回 `JWT_SECRET`，用 MultiFernet 平滑换密钥）、推送、每分钟比对版本补推；接口地址在正式模式下不允许解析到内网 / 本机 / 元数据地址（防 SSRF），自建模型需在 `.env` 打开 `MODEL_ALLOW_PRIVATE_BASE` |
| 换向量模型 | 后台线程用新模型把全部知识块重新向量化，校验维度；全部算完再一次性写入并切换分组，中途失败不改任何东西；重建期间新上传的文档在最后补上 |
| web | 「模型接入」页分三块：默认模型（对话、重排的主用 / 备用排序；向量模型切换 + 进度条）、内置厂商、自定义厂商（常用厂商一键填地址，逐个模型测试并自动勾选能力） |

## 关于「Key 存数据库是否更安全」
如实回答：比明文放 `.env` 好（备份里是密文、只显示末 4 位、改动有日志、换 Key 不用登服务器），但解密密钥也在同一台服务器上，防不住整机被攻破。因此加了独立的 `MODEL_KEYS_SECRET`（正式模式必须设置），并在部署指南里写明备份与 `.env` 分开存放、在厂商后台设消费上限。

## 问题与修正（本阶段 AI 自己的错误）
| 问题 | 怎么发现的 | 修正 |
|---|---|---|
| 上一版只做了 Key，没考虑地址为空的情况 | 用户反馈混元仍提示 `api_base not configured` | 地址内置官方默认值，并开放网页修改 |
| 自定义模型别名可能和分组名撞（标识 `chat` + 模型 `agent` = `chat-agent`），网关会拒收整份配置、之后每次同步都失败 | 写完后自查别名规则 | core 保存时就拒绝，补测试 |

## 测试
- gateway：叠加配置（Key / 地址 / 协议、自定义厂商、分组过滤与回退、校验）、测试连接不回显 Key、能力检测与维度。
- core：只有管理员、加密不回显、地址 / 协议修改、内网地址拦截、自定义厂商增删改、默认模型校验、网关重启补推、网关不可达先存后推、换密钥后旧密文可解 / 两个都换后提示重填、切换向量模型成功与失败（失败时向量和分组都不变）。
- web：别名规则与后端一致、候选模型过滤、排序、表单改动判断。

## 后续：页面简化
用户反馈页面「乱，找不到重点」。原因是把所有能力平铺在一页上，还露出了别名、协议、适配名等实现细节。改为：
- 顶部一行状态：AI 能不能用，对话 / 知识库 / 重排各自在用哪家；
- 中间每家厂商一行，只填 Key、测试、保存；
- 主备顺序、换知识库模型、接口地址和协议、其他厂商全部收进默认折叠的「高级设置」；
- 文案统一缩短。
