# 个人模式、报价分享链接、新手引导、语音输入

- 日期：2026-10-31 ｜ 工具：Claude Code（单 agent）｜ 模块：core / web

## 任务目标
用户看完「完善程度与易用程度」评估后要求把缺项补上，并说明真实用法：
「我自己用的话主要是出方案给甲方然后直接开发」。一个人接单时，团队版的角色（销售提交、主管审批、管理员配置）是负担。
和用户确认的做法：

| 问题 | 选择 |
|---|---|
| 一个人用时角色太重 | 业务规则里的「个人模式」开关：审批规则触发时自动通过（原因照常记录），主管账号可以进系统配置，隐藏团队相关页面 |
| 方案怎么交给甲方 | 生成可分享的只读报价链接（有效期、可撤销、甲方打开时提醒） |
| 语音输入 | 浏览器自带识别（不支持的浏览器不显示话筒按钮） |
| 新手引导 | 工作台上的上手清单 + 关键页面的首次提示 |

不做（和用户说明过）：上线部署需要服务器；外部情报真实数据源需要付费接口；多公司隔离一个人用不需要。

## 第 1 步：个人模式
- `rules.yaml` 新增 `org.solo_mode`（默认关），业务规则页「工作方式」分组里开关。
- 报价、报销触发审批规则时：个人模式下直接「已审批」，动态写「个人模式免审批（提醒：毛利 10.0% 低于底线…）」，风险不丢。
- `app/common/permissions.can_configure`：管理员，或个人模式下的主管。行业包、业务规则、模型接入、定时任务、战卡、消息推送这 6 处原来各自写 `role == ADMIN`，统一改为它；成员与团队仍只有管理员。
- `/api/me` 返回 `solo_mode`；前端导航换成「工作区 + 设置」，去掉审批、业绩目标、日报、成员与团队；工作台不显示「待我审批」，不叫「团队」；左下角角色显示「个人模式」。
- 测试：`test_solo_mode_api.py`（默认团队模式、主管能配置但不能管成员、销售仍不能配置、低毛利报价免审批且动态记原因、超标报销免审批且仍标超标）；`nav.test.ts`、`permissions.test.ts` 补个人模式用例。
