# 按钮与链路闭环审查：每个按钮有意义、每条通知能点到记录

- 日期：2026-10-31 ｜ 工具：Claude Code（单 agent）｜ 模块：web / core

## 任务目标
用户要求「确保按钮什么的都有意义，整条链路能形成闭环」。逐页点一遍按钮，再按业务链路（线索 → 商机 → 报价 → 审批 → 合同 → 回款 → 提成；报销 → 审批；AI 写操作 → 记录）检查每个状态有没有下一步入口、每条提醒能不能直接打开要处理的记录。

## 怎么查的
- **按钮爬取**：临时 Playwright 脚本，销售 / 主管 / 管理员 × 25 个页面，逐个点击可见按钮。写请求一律在浏览器里拦下（不落库），以「页面有变化 / 发了请求 / 跳转 / 弹窗 / 下载」判断按钮有没有作用，同时收集控制台错误、≥400 的接口和没有名字的按钮。
- **状态机**：对照 core 的状态流转和前端的可用操作。报价被驳回退回草稿可改后重提、报销被驳回可「重新提交」、赢单 / 输单为终态且撤销只对普通阶段生效，前后端一致。
- **通知深链**：查库里所有通知的 link 格式，逐个对照前端页面是否读取对应参数。

## 发现与修正
| 问题 | 影响 | 修正 |
|---|---|---|
| 左上角「SalesPilot」是个下拉，里面只有当前这一个工作区 | 点了没有任何意义 | 改为点击回工作台的品牌链接，去掉下拉 |
| 侧栏开关只有 title 没有 aria-label | 读屏 / 自动化里是无名按钮（每页都有） | 补 aria-label |
| 待审批 / 催办通知跳 `/approvals`、`/approvals?id=`，页面不读 id | 主管点通知后还要自己在列表里找 | 待审批通知也带审批 id；页面定位到这一条并高亮，不在待处理就切到「已处理」，都没有再提示 |
| 报销审批结果通知跳 `/expenses?id=`，页面不读 id | 点通知只到列表 | 打开这张报销单 |
| AI 确认执行后「查看记录」：报销、阶段、审批、任务都只到列表页 / 工作台 | 写完找不到刚写的那条 | 直接打开那条记录（任务定位到所在商机 / 客户的任务） |
| 销售 / 主管打开「消息推送」「模型接入」页仍请求管理员接口，返回 403 | 控制台报错，页面本身只显示锁定提示 | 非管理员不发请求 |
| 「后端开发中」「接口开发中」的兜底文案和 `ComingSoon` 占位 | 所有接口都已实现，这些分支是死代码；唯一能触发的情况（前后端版本不一致导致 404）会误导成「还没做」 | 删除；版本不一致改为提示刷新或更新服务 |

## 爬取里的误报（核对后不改）
- 打印页的「打印 / 存为 PDF」：脚本把 `window.print` 换成了空函数，所以看起来没反应。
- 规则页「报价与审批」：本来就是当前选中的标签。
- 看板「新建」点击超时：前一个弹层还在关闭，单独点能正常打开新建商机。

## 测试
- core：`test_done_links_open_the_written_record`（AI 执行后的记录入口）、待审批通知 link 带审批 id。
- web：版本不一致的提示不再说「开发中」，业务 40401 不受影响。
- 浏览器：通知深链定位高亮、找不到时切到已处理并提示、报销单直接打开、品牌链接回工作台、非管理员不产生 403（临时脚本，写请求全部拦截，不留测试数据）。
