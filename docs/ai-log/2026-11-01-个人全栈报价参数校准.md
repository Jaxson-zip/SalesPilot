# 个人全栈报价参数校准

- 日期：2026-11-01 · 开发者：Claude Code · 模块：core / packs/software_outsourcing

## 任务卡
- **背景**：按预算收缩经济版后，¥3 万预算只放得下「登录」一个模块。根源在个人全栈参数偏高。
- **用户给的参数**：
  - 个人开发日单价 ¥400。
  - AI 写代码约快一倍。
  - 主要时间花在架构和需求上，需求清晰时开发很快。
- **范围**：`catalog.json`、`rules.yaml`、`configurator.py`（架构人天、个人服务项）、知识库《软件外包报价说明》。

## 做了什么
1. `DAY-FULLSTACK` 售价改为 ¥400/人天，成本 ¥200/人天，成本比例沿用原来的约 53%。
2. `solo_ai_factor` 从 0.7 改为 0.5。
3. 架构与数据库设计不再乘 AI 提效系数：按用户说的「主要是架构」，这部分要人想清楚。
4. 新增个人交付的部署、运维、源码交付服务项（`-SOLO`），按人天折算：
   - 部署 2 天 ¥800；
   - 运维 1 天/月 ¥400；
   - 交付培训 1 天 ¥400。
   - 原因：原来个人交付也用团队价，部署 ¥5,000、运维 ¥6,000/月，在 ¥400 的日单价下占了报价的一半。
5. 知识库《软件外包报价说明》同步更新提效系数和个人服务项。

## 效果（晨光烘焙蛋糕预订小程序，9 个模块，小程序 + 后台，个人交付）

| | 校准前 | 校准后 |
|---|---|---|
| 经济版 | ¥89,000 | ¥19,600 |
| 标准版 | ¥101,000 | ¥21,600 |
| 高配版 | ¥148,000 | ¥25,600 |

- 三档毛利 43–44%，都过 25% 的底线。
- 三档都在 ¥3 万预算内，不再需要收缩。

## 校验与兜底
- 学习问答的测试 `test_business_overview_has_catalog_rules_and_no_cost` 挂了，代码本身没错，是测试写得脆弱：它用子串检查「成本价不能出现在给新人看的数据里」。新的成本价 ¥200 恰好是目录价 ¥200,000 的前缀，于是被误判。改为按完整金额匹配。
- `test_solo_fullstack_pricing` 改为断言新单价、个人服务项、架构不打折。
- 个人服务项的天数（部署 2 天、运维 1 天/月、交付 1 天）是按经验估的，没有经过用户确认。可以在「行业包配置 → 产品目录」里改。
