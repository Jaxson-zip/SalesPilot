# 多角色压测：故意发不合理的请求，看 AI 和接口怎么处理

- 日期：2026-11-01 · 开发者：Claude Code · 模块：core（Agent 工具与提示词、表单校验）、web（合同页）

## 任务卡
- **背景**：用户要求在本地环境模拟真实使用，分别扮演销售、主管、管理员，故意发不合理或越权的内容，找出问题并修复。
- **做法**：
  - 写了一个场景脚本，在 core 容器内用真实模型（DeepSeek）逐轮对话，记录工具调用、确认卡片和回复。
  - 销售 20 个场景、主管和管理员各约 10 个场景。
  - 另外用脚本直接调 REST 接口，传超大金额、负数、离谱日期、空白标题等。

## 发现与修复

| 角色 | 场景 | 问题 | 修复 |
|---|---|---|---|
| 销售 | 「并发 100 万人」「并发 -10 人」 | 回复「还需要确认：并发用户数」，没说给的值不合理 | `invalid_fields` 按需求模型的上下限给出原因：「你给的是 1000000，不能超过 10000」 |
| 销售 | 「质检助手那单丢了」 | 只按客户名搜，商机名搜不到 | `search_by_opportunity` 兜底按商机名找（同样按数据范围过滤） |
| 销售 | 「明天上午拜访了…已经决定签约」 | 当成已发生的拜访记跟进 | 工具规则：未来日期的「已发生」先确认是记错日期还是计划 |
| 销售 | 报销下周的住宿 | 追问入住日期，没先说未发生的费用不能报 | 同一条规则补充：未来费用不能报销 |
| 销售 | 「我这个月提成多少」 | 没有工具可查，只能让销售自己报合同 | 新增 `list_contracts`（合同、回款、逾期、预估 / 已确认提成） |
| 销售 | 转走同事的客户 | 建议找「主管或系统管理员」 | 销售的角色限制：找团队主管，不找管理员 |
| 主管 | 转移客户负责人 | 让去找管理员 | 指引到「客户」页批量转移 |
| 主管 | 「以张晨的身份记跟进」 | 把同事张晨当成客户联系人 | 系统提示词加「公司内部同事」名单 |
| 主管 / 管理员 | 本月业绩、谁落后、哪些合同逾期、某人提成 | 只有累计漏斗，答不了按月、按人的问题 | 新增 `team_targets`；`pipeline_summary` 摘要注明是累计口径 |
| 管理员 | 禁用账号、重置密码 | 说管理员没有权限、找 IT | 指引到设置页「成员与团队」 |
| 管理员 | 帮我报销 | 先问了一堆报销信息，最后才说不能报 | 第一句就说明管理员不能提交报销 |
| 接口 | 商机金额 2^63 | 500（bigint 溢出） | `Amount` 上限 100 亿元，超出返回校验错误 |
| 接口 | 金额 10^17、预计成交日 1900 年、任务截止 1970 / 2999 年、空白任务标题 | 都被接受 | 金额上限；日期限 2000 年后、10 年内；任务标题去空白后必填 |
| 页面 | 合同页「本月预估提成」 | 显示的其实是全部合同的累计值 | 改名为「累计预估提成」，本月数字看工作台 |

## 校验与兜底（AI 写错、人工 / 复测修正的地方）
- **合同工具的合计口径**：第一版 `list_contracts` 按负责人或逾期筛选时，摘要照搬可见范围内全部合同的合计。结果张晨名下显示「本月新签 ¥92,000」，那其实是李薇签的。复测时发现后改为只按筛出的合同合计，并补了断言。
- **提示词把内部说法带进回复**：角色限制里写着「没有这些写工具」「管理员对业务数据只读」。模型原样说给用户：「因为对话里没有报销的写工具」；销售问转客户时，冒出「系统对业务数据只读」。已改写措辞，并要求只说账号权限、不提工具。
- **工具注册表测试**：新增两个工具后，`test_registry_matches_spec` 没同步更新，全量测试失败 1 个，已补。
- **ruff --fix 删掉了 `solution.py` 里 `missing_labels` 的再导出**：调用方改为从 `requirement_brief` 导入。

## 事故：测试时真的推送了企业微信
- 销售场景 s04 模拟了「确认赢单」。本地 `.env` 配的是真实企业微信机器人，于是群里收到了一条赢单喜报（16:26 UTC，日志里 POST 返回 200）。
- 之后的本地压测一律不在会推送企业微信的操作上点确认（赢单、提交报价 / 报销审批），只确认记跟进、建任务这类操作。

## 没修 / 按设计保留
- **没有报价也能赢单**（会发喜报）：目前是业务上允许的，是否要拦截需要产品决定。
- **没有待确认操作时调 resume**，回复为空：只有直接调接口才会遇到，界面上没有入口，暂不处理。
- **阶段名称**：管理员问业绩时，模型偶尔用不规范的阶段叫法，影响小。
- **按 UTC 算「今天」**：跨北京时间 08:00 时，日期相关的用例偶发失败（见上一篇 ai-log），待排查。
