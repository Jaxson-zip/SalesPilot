# 自查与本地生产环境浏览器巡检

- 日期：2026-11-01 · 开发者：Claude Code · 模块：infra / CI / web / core（行业包、模板）

## 任务卡
- **背景**：用户要求自查最近的改动，用浏览器访问 crm.jaxson.bond 模拟操作，发现问题就迭代修复。
- **访问情况**：
  - 本机访问线上站点失败：HTTP 无响应，HTTPS 握手失败，服务器 IP 直连也一样。
  - 用户同意改为在本地生产环境测试：`docker compose --profile prod`，地址 http://127.0.0.1:8080。
- **范围**：nginx 配置、自动部署脚本、AI 工作台示例、对话区滚动、报价单打印权限。

## 发现与修复

### 1. 本地 `--profile prod` 起不来（nginx 找不到证书）
- **现象**：nginx 启动即报错退出，日志为 `cannot load certificate "/etc/nginx/certs/fullchain.pem"`。
- **原因**：提交 abd3fcd 把服务器上手改过的 HTTPS 配置直接写进了入库的 `default.conf`，而本地没有证书。
- **修复**：
  - `default.conf` 恢复为只有 HTTP。
  - `https.conf.example` 改名为入库的 `https.conf`，`server_name _` 不写死域名。
  - `docker-compose.prod.yml` 把 `https.conf` 挂载成 nginx 的 `default.conf`，服务器上不再需要改入库文件。
  - 两份配置都用 `nginx -t` 校验通过：HTTPS 那份用一次性自签证书。
  - 同步更新《上线部署指南》第三节。

### 2. 自动部署实际没有更新线上（GitHub Actions 日志）
- **现象一：服务器上 `git pull` 每次都失败**。日志为 `Your local changes … infra/nginx/default.conf`，原因是服务器手改了这个文件。
- **现象二：拉镜像失败被吞掉**。
  - compose 默认镜像名是 `salespilot-core:latest`，服务器去 DaoCloud 镜像站拉，返回 `这镜像不在白名单`。
  - CI 推到 ghcr 的镜像从来没被用上。
  - `pull || true` 把这个错误吞掉了，流水线显示成功，线上其实一直跑旧镜像。
- **修复**：部署脚本做了四处改动。
  1. 加 `set -e`。
  2. 同步代码改用 `git fetch` + `git reset --hard origin/main`。`.env`、证书不在版本库里，不受影响。
  3. 登录 ghcr，拉本次 commit 的镜像，打成 `salespilot-*:latest`。这样手动执行 `dc up -d` 也会用到新镜像。
  4. 用 `trap` 保证退出时登出 ghcr。
- **未验证**：只有推送后跑一次流水线才能确认。需要确认两点：
  - 阿里云服务器能否顺利访问 ghcr.io；
  - ghcr 包权限是否允许 `GITHUB_TOKEN` 拉取。

### 3. 「出方案报价」示例卡片和当前行业包对不上
- **现象**：团队默认是软件外包，示例卡片却是「Qwen3-32B 私有化方案」。点卡片会直接发送，发出去的是大模型部署需求。
- **修复**：
  - 每个行业包的 `pack.yaml` 增加 `example_prompt`，`/api/packs` 返回这个字段。
  - `templates.yaml` 里的出方案卡片标上 `pack_example: true`。
  - 前端按当前行业包替换例句，优先级：商机的产品线 → 下拉框选择 → 团队默认。
- **同类问题**：对话中输入框的占位例句「换成 DeepSeek-V3 再算一版」也改为与行业包无关的说法。

### 4. 报价单未审批也能打印
- **来源**：用户反馈。
- **现象**：草稿、待审批、已驳回的报价单都有「打印报价单」按钮，打出来的 PDF 就能发给客户，绕过了主管审批。
- **修复**：
  - 新增 `canPrintQuote`，规则与分享链接一致：approved / sent / accepted 才能打印。
  - 详情页隐藏打印按钮。
  - 直接打开打印地址时只显示提示，打印按钮和「显示大写金额」也不显示（规则 18）。
- **测试改动**：e2e `v3.spec.ts` 先断言草稿不能打印，提交（自动审批通过）后再打印；`mobile.spec.ts` 改为选已审批的报价单。

### 5. 对话区滚动跟随（加固，未在浏览器里验证）
- **现象**：确认需求后，三档报价出来了，视图却停在需求卡片上。
- **排查**：
  - 复查时发现浏览器面板处于隐藏状态，页面不渲染。我自己挂的 scroll 和 ResizeObserver 监听都没有触发，这个现象很可能是测试环境造成的假象。
  - 代码里确实存在一个竞态：程序滚到底后内容又突然变高，接着到来的 scroll 事件按新高度判断成「用户翻看」，会把跟随关掉。
- **加固**：抽出纯函数 `nextStick`，只有往上翻才停止跟随，并补了单元测试。

## 校验与兜底
- **AI 写错的地方**：nginx HTTPS 配置被直接写进入库的 `default.conf`，破坏了本地 prod profile。这次改为由 prod compose 叠加挂载。
- **AI 判断失误**：一开始把「不跟随滚动」当成已确认的 bug。后来发现浏览器面板隐藏时页面不渲染，又做了对照实验：连自己挂的监听都不触发。所以如实记为「加固，未验证」。
- **没修的**：页面整页加载时侧边栏先展开、再按折叠偏好收起，有一下动画。站内跳转不受影响。
- **测试数据**：巡检看到的 E2E 测试残留数据（金额 0.01 的商机、`mvwf…` 待办）由 `seed --reset` 清理，不是 bug。
