# 行业包被已有商机覆盖、AI 金额单位换算错误

- 日期：2026-11-01 · 开发者：Claude Code · 模块：core（Agent 出方案、工具结果）

## 任务卡
- **背景**：线上试用发现两个问题，用户要求先核实是否准确，准确就修。
- **结论**：两条都准确，都已在本地复现并修复。

## 1. 手选软件外包，却被带进电脑采购流程
- **现象**：
  - 手选「软件外包」，说「给星河设计工作室做一个微信预约小程序」，AI 追问「普通办公、设计各配几台电脑」。
  - 用户纠正后，AI 仍然重复这个问题；重新打开会话，显示的是自动匹配的「企业办公 IT」。
- **原因**：
  - 出方案时会按消息里的客户名自动关联客户。演示客户「星河设计工作室」恰好只有一个进行中的商机「IT 设备换新」，产品线属于企业办公 IT，于是这个商机也被一并关联。
  - 一旦关联了商机，就以商机的产品线为准，手选的行业包被忽略：`choice = None if opp_id`。
  - 商机 id 还写进了会话状态，所以之后几轮、以及重新打开会话时，都沿用了企业办公 IT。
- **修复**：新增 `agent/nodes/customer_link.py`，把客户关联和行业包选择从 `solution.py` 拆出来，新增 `choose_pack`。
  - **从商机进入**：仍以商机的产品线为准。
  - **自动关联的商机和手选行业包冲突**：以手选为准，按新项目处理。只关联客户、不关联商机。
    - 回复开头说明：「星河设计工作室已有进行中的商机「IT 设备换新」（企业办公 IT），这次按你选的「软件外包」当作新项目出方案……如果其实是同一个项目，请从该商机详情进入 AI 工作台」。
    - 追问、需求卡片、方案说明三条回复路径都带这段说明（`emit_notice`）。
  - **没手选**：仍自动关联唯一的商机，行为不变。前端只有在用户动过下拉框时才传 `pack`，所以「手选」是可靠的信号。
- **简化**：原建议是「让用户选择关联已有商机还是新项目」。这次没做选择卡片，改为默认按新项目处理并给出说明，用户想关联已有商机时从商机进入即可。

## 2. AI 把 46 万元说成 460 万元
- **现象**：商机金额 ¥460,000，AI 回答「金额 460 万元」，用户追问核对后才改口。
- **原因**：工具结果把整数「分」原样交给模型（`"amount": 46000000`），让模型自己除以 100 再换算成万元，容易错一位。
- **修复**：
  - 新增 `agent/money.py`：工具结果回传给模型前，给每个金额字段补一个 `<字段>_text`，例如 `amount_text: "¥460,000（46 万元）"`。
    - 原来的分值保留，因为模型调用工具时参数仍按分传。
    - 哪些字段算金额按字段名判断：`amount` / `price` / `cost` / `commission` / `budget` / `balance` 结尾，或者是 `estimated` / `confirmed`。`total`、`paid` 这类可能是数量的字段不算。
  - 工具规则新增一条：金额直接照抄 `_text` 的写法，不要自己除以 100 或换算成「万」。
  - 系统提示词里的「当前这单」也改用同一个格式化函数。

## 校验与兜底
- **AI 之前写错的地方**：上一轮修「选的行业包被团队默认覆盖」（c0dee96）时，只处理了「没关联商机」这一种情况，漏掉了「按客户名自动关联到商机」也会覆盖手选的情况。这次补了回归测试。
- **顺带处理**：`solution.py` 原本 446 行，超过 400 行上限。拆出客户关联后是 406 行，仍略超，后续再拆。
- **追加修复（用户要求）**：真实模型在用户第二轮纠正时，说「上一轮我还没有真正生成方案」，又问了一遍是否需要管理后台。
  - **原因**：这一轮走的是对话循环，模型只拿到一句「这个会话已经在出方案（有需求草稿）」。它不知道需求卡片已经发出、正在等确认，也不知道草稿里已经有哪些信息。
  - **修复**：新增 `agent/requirement_brief.py`，「方案进行中」说明改为写清三件事：
    - 当前在哪一步：需求卡片已发出，等销售确认；或者需求已确认。
    - 草稿里已有的信息：字段名取自行业包的需求模型，并要求模型不要再问这些。
    - 用户只是纠正方向时怎么回：简短确认按哪个行业包处理，并提示去卡片上核对。
  - **复验**：真实模型跑了两次，第二轮都回答「需求卡片里已经拆好 8 个功能模块……交付端微信小程序 + 管理后台，预算 10 万元、6 周」，并引导确认，不再重复追问。
  - **测试**：`tests/unit/test_requirement_brief.py`。
- **测试不稳定（与本次改动无关）**：有一次全量测试恰好跨过北京时间 08:00（UTC 零点），任务「今天到期」、离店日期等 4 个按日期判断的用例失败；单独重跑和整套重跑都通过。说明有地方用 UTC 日期算「今天」，后续排查。
