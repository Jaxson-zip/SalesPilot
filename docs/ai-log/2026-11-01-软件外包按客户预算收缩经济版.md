# 软件外包按客户预算收缩经济版

- 日期：2026-11-01 · 开发者：Claude Code · 模块：core / packs/software_outsourcing

## 任务卡
- **背景**：接单流程测试里，客户「深圳晨光烘焙工作室」预算 ¥3 万，推荐方案却是 ¥9.2 万。原逻辑在预算连经济版都放不下时只在摘要里提示「建议砍掉部分功能或分期」，三档价格都远超预算。
- **目标**：客户给了预算时，经济版要放进预算。
- **约束**：价格只能由规则代码算（AGENTS.md §4.5），所以不压单价、不打折，只收缩范围；毛利规则照常校验。
- **范围**：新增 `software_outsourcing/budget.py`，`configurator.configure` 调用；`rules.yaml` 的 economy 档加 `fit_budget: true`（管理员可在行业包配置里关掉）。

## 做了什么
1. 预算低于经济版时，先把经济版的模块都改为「简单」复杂度，放得下就停。
2. 还放不下，就一个一个把模块挪到二期，直到放进预算：先挪 AI 推断、客户没提的模块，再挪客户提到的；各自从排在后面的开始。
3. 摘要写明怎么收缩的，例如「按客户预算 3.0 万收缩：功能按基础版做；二期再做：在线支付、会员积分」。
4. 只剩一个模块还放不下时不收缩，经济版保持原样，并保留原来的预算缺口提示。
5. 标准版、高配版不变，销售可以拿来对比和争取预算。

## 校验与兜底
- 第一版回归测试的预算取错了：拿「只做会员登录」的价格当预算，去测「在线预约 + 会员登录」的组合。在线预约就算做成基础版也比会员登录贵，单独放不下，于是函数按设计返回原经济版，断言失败。改为用「只做在线预约」的价格当预算。
- 实测当前参数（个人全栈 ¥1,500/人天、AI 提效 0.7、架构 5 天、后台框架 4 天，另有测试、UI 等比例）：
  - ¥3 万只放得下 1 个模块（16 人天，¥2.9 万，毛利 47%）。
  - ¥5 万能做 4 个模块。
  - 全部 8 个模块要 ¥8.9 万。
  - 收缩逻辑本身没问题，但报价偏高的根源在人天参数。参数是否校准由用户决定，没有擅自改。
