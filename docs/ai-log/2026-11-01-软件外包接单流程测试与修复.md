# 软件外包接单流程测试与修复

- 日期：2026-11-01 · 开发者：Claude Code · 模块：core / agent / web

## 任务卡
- **背景**：在浏览器里按真实接单流程走了一遍（单人模式，经理账号）：新客户「深圳晨光烘焙工作室」→ 商机「蛋糕预订小程序」（软件定制开发）→ AI 出需求卡和三档方案 → 报价单 → 分享链接给客户接受 → 生成合同（里程碑 30/30/30/10）→ 登记首笔回款 → 赢单，企业微信推送 200。链路是通的，但发现下面几处问题。
- **目标**：修掉流程里看得见的错误和卡住的状态；配置类、业务口径类的问题只记录，不改。
- **范围**：`agent/nodes/solution.py`、`agent/nodes/respond.py`、`web/lib/{labels,agent-labels,contract}.ts`、`PaymentDialog.tsx`、`RequirementCard.tsx`，以及已在 cbd112a 里提交的行业包条款、行业包选择、客户页新建商机。

## 发现的问题和处理

| # | 问题 | 处理 |
|---|---|---|
| 1 | 软件外包报价单的条款是硬件的（交货、质保） | 行业包 `pack.yaml` 可覆盖 `quote_terms`，付款方式按行业包回款计划填（cbd112a） |
| 2 | 没关联商机时只能用团队默认行业包，问软件外包也按 GPU 问需求 | 输入框加行业包下拉，`ChatIn.pack` 校验后写进 `state.pack_choice`（cbd112a） |
| 3 | 客户详情页不能直接新建商机 | 客户页加「新建商机」，客户预填（cbd112a） |
| 4a | 对话里生成报价单后没有入口 | `save_quote` 推送 `action_result`，确认卡片显示「已完成 · 查看」 |
| 4b | 回复里出现「已通过 check_margin 校验」 | 交给模型的工具结果改用中文步骤名，并要求不写函数名 |
| 4c | 确认卡片一直停在「正在执行…」 | 同 4a，按执行结果显示 |
| 4d | 需求卡确认后一直显示「正在生成正式报价」 | 改为「需求已确认，正式报价在下方生成」 |
| 5a | 动态里分享 / 查看报价显示英文事件名 | `labels.ts` 补 `quote.share`、`quote.share_revoked`、`quote.viewed` |
| 5b | 登记回款金额要手算 | 预填下一期未收金额（不超过未收总额），提示期次名称 |

## 校验与兜底（AI 写错、人工修正）
- **行业包选了软件外包，AI 还是按 GPU 问需求**：前端和 state 都对了，但 `parse_requirement` 又调了一次 `deps.resolve_pack(opp_id)`，按团队默认重新取。改为没关联商机时优先用 `state.pack_choice`，补回归测试 `test_solution_flow_uses_chosen_pack`。
- **把 `action_result` 写进 state 后 AI 回复消失**：respond 看到 state 里的 `action_result` 会改用固定的执行结果文案（`message.replace`），整段方案说明没了。改为只推送 artifact、不写 state。
- **artifact 顺序**：先推 `action_result` 再推 `quote`，有测试取第一个 artifact 当报价单，挂了。改为先推 quote。
- 另一个工具在 cbd112a 里把 1–3 项连同 CI 改动一起提交并推送了，这里没有改写那次提交，剩下的修复单独提交。

## 没改的（需要用户决定或部署时配置）
- 分享链接用的是 127.0.0.1：部署后设置 `WEB_BASE_URL`。
- 打印页公司名是「SalesPilot 演示公司」：`PRINT_COMPANY`，换成真实公司名。
- 估算偏高：客户预算 ¥3 万，推荐档 ¥9.2 万，人天参数需要按实际报价校准。
- 自己接软件外包时，把团队默认产品线设成软件定制开发，省得每次选。
