# 复测流程断点：输单收尾、草稿补关联客户、审批后修改路径、报销去审批

- 日期：2026-11-02 · 开发者：Claude Code · 模块：core（商机、报价）、web（报价详情、报销、输单弹框）
- 上一份：`2026-11-02-用户体验复测修复.md`

## 任务卡
- **背景**：用户实际走流程时发现 4 处断点（1 高 3 中），附截图。
- **做法**：逐条确认根因；能在后端兜住的规则放到 service 层，前端只负责显示入口和确认。

## 逐条核实与修复

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 高 | 输单后关联报价仍能提交并自动通过，商机仍提示「报价已审批，还没发给客户」，首页还有报价跟进待办 | 阶段改成输单只写了原因和关闭时间，没有处理商机下的报价、审批和待办；报价流转和出报价都不检查商机是否输单；推进建议对终态商机仍算「报价未发送」 | 新增 `opportunity_close.close_lost`：输单时把草稿 / 待审批 / 已审批 / 已发送的报价改为新状态「已关闭」（closed），待审批的审批单驳回（备注「商机已输单，自动关闭」），商机下未完成的待办自动完成。阶段动态里写明关了几张报价、几条待办。新增 `quote_validity.ensure_deal_open`：输单商机不能再出报价（AI 和手工）、提交、发送、接受、续期、撤回修改、复制新版本、关联（42201 `opportunity_lost`）。输单商机不再给任何推进建议。输单弹框写明会关闭报价和待办 |
| 中 | AI 报价没识别出客户，提交被禁用，没有补关联入口，只能重新生成 | 后端没有修改草稿关联的接口 | 新增 `PATCH /api/quotes/{id}/link`：草稿可以选客户，或选商机（用商机的客户），物料和价格不动；关联商机时，商机还在线索 / 需求确认阶段的推进到方案报价。前端在没有客户的草稿上显示「关联客户」，隐藏提交按钮（原来是置灰，不符合规则 18） |
| 中 | 报价审批后没有继续议价和修订的路径 | 状态机只有往前走的流转 | 已审批、还没发送的报价可以「撤回修改」（`POST /revise`）：退回草稿、清掉固化内容，改完重新提交审批。已发送 / 客户拒绝的报价可以「复制为新版本」（`POST /revisions`）：新建草稿，记 `revision_of_id`（迁移 0029）。新版本发给客户后，原报价自动关闭，跟进任务一并完成。已有修订中的新版本时不再复制。详情页显示「修订自 / 新版本」 |
| 中 | 主管从审批中心打开报销，核对票据后只有「关闭」 | 报销侧栏没有像报价详情那样的去审批入口 | 主管打开待审批的报销时，底部显示「去审批」，直接跳到审批中心对应的那一条 |

## 校验与兜底
- **新状态 closed，而不是复用「已驳回」**：报价的「已驳回」在前端显示的是客户拒绝，输单关闭和被新版本替代都不是客户拒绝。单独一个「已关闭」，统计和筛选不会混。
- **输单时待审批的报价**：只改报价状态的话，审批中心里还会挂着一条待审批。所以对应的审批单一起驳回。没有新增审批状态，备注里写原因。
- **一个旧单测失败**：`test_lost_sets_reason_and_closed_at` 用的 `FakeSession` 没有 `scalars`。输单收尾要查报价和待办，就给假 session 加了返回空结果的 `scalars`，测试原有的断言不变。
- **文件行数**：`opportunity_service.py` 原来 411 行，超过上限。这次把赢单喜报挪到 `opportunity_close.py`，现在 396 行。`quote_service.py` 397 行，修订逻辑放在新文件 `quote_revision.py`。
