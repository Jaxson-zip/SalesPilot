# 手机端 AI 工作台新对话页右侧被裁

- 日期：2026-11-02 · 开发者：Claude Code · 模块：web（AI 工作台、手机端 e2e）
- 上一份：`2026-11-02-自动关联商机后手选行业包失效.md`

## 任务卡
- **背景**：用户用真实手机打开线上 AI 工作台，新对话页右边一截被裁掉：提示条、副标题、输入框和下面的示例卡片都缺了右边。
- **做法**：本地按手机宽度复现，找出把页面撑宽的元素，修复后补一个能查出这类问题的检查。

## 原因
- 输入框工具栏（行业包、附件、样例、语音、模型）排成一行，不换行，最小宽度约 420px。
- 它所在的列（`ai/page.tsx` 里的 `flex min-h-0 flex-1 flex-col`）是横向 flex 的子元素，没有设 `min-w-0`。flex 子元素默认不会窄于内容的最小宽度，于是整列被撑到约 454px。
- 外层卡片设了 `overflow-hidden`，超出的部分被直接裁掉，页面本身不出现横向滚动。
- 之前的手机端 e2e 和我上一轮的检查只看 `scrollWidth` 是否大于屏宽，所以都没查出来。上一轮说「48 次都没有横向溢出」，这个结论不够，说明这种检查有盲区。

## 修改
- `app/(main)/ai/page.tsx`：这一列加 `min-w-0`。
- `components/agent/Composer.tsx`：工具栏加 `flex-wrap`，窄屏时模型选择和发送按钮换到第二行。
- `e2e/mobile.spec.ts`：
  - 新增 `clippedInMain`：找出 `main` 里超出屏幕右边的可见元素，不算横向滚动容器里的元素；
  - 原来只测 390 宽，加上 320 宽。

## 校验与兜底
- 用同样的「超出右边的可见元素」检查，修复前在本地扫了 12 个页面、3 种宽度（320 / 360 / 414），只有 AI 工作台不合格。其他页面没有这个问题。
- 修复后重建本地 web，在 320、360、390、414、430 五种宽度下检查 AI 工作台新对话页、工作台、报价，都没有超出的元素。360 宽截图看了一遍，布局正常。
- `pnpm lint`、`pnpm typecheck` 通过。
- `mobile.spec.ts` 没能在本地跑：`.env` 开着企业微信推送，浏览器测试的前置检查拦下了。需要先按提示临时关闭推送才能跑。
