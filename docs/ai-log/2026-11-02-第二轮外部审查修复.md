## 任务卡
- **背景**：另一个 agent 又审查出 8 个问题。用户要求逐条重新核实、修复，再自己排查一遍线上。
- **做法**：每条先在代码里找到根因再改；每条都补了回归测试，其中 4 条在旧代码上跑过、确认会失败。

## 逐条核实与修复

| # | 问题 | 核实结果 | 修复 |
|---|---|---|---|
| 1 | 同价的新方案返回旧报价单 | 成立。`save_quote` 的幂等键是 `agent:会话:档位:总价`，同一会话再确认一版同档同价的方案会命中旧单 | `confirm` 节点在 interrupt 之后生成 `confirm_id`（随结果写进 checkpoint，保存报价重试时不变，下一次确认换新的），键改为 `agent:会话:confirm_id`。`create_from_tier` 命中旧键时比对档位、总价、物料，不一致返回 40901 |
| 1+ | （顺带）工具写操作的键 `agent:会话:call_id` | 同类隐患：有的厂商按序号给 call_id（`functions.x:0`），同一会话下一轮会重复 | 键里加消息序号 |
| 2 | 旧报价链接的范围随新需求变化 | 成立。分享页读商机当前的需求清单，条款按当前模板生成；打印页在前端也一样 | `quotes.snapshot`：提交审批时固化项目范围和条款（`quote_snapshot.py`），详情、分享页、打印页都读它；草稿仍按当前需求显示；迁移前已提交的报价在第一次分享时补快照 |
| 3 | 回款登记没有防重复 | 成立。合同行锁只防余额超额，识别不了同一次登记的重试 | `PaymentIn.idempotency_key`（前端每次打开登记框生成一个，重试沿用）：同键同内容直接返回，不同内容 40901；同一银行流水号已登记且没冲正时返回 42201 `payment_duplicate_reference`，提示先核查 |
| 4 | 多人同时新建单据撞号 | 成立 | 新表 `code_counters`，`INSERT … ON CONFLICT DO UPDATE … RETURNING` 原子分配；计数器落后于已有单号时从已有最大值往后接；`seed --reset` 一起清 |
| 5 | 舍入口径不一致 | 成立，而且有三种口径：后端 Python `round` 是银行家舍入（94.5→94）；报价编辑页是原价减四舍五入的折扣额（94）；方案预览 `Math.round(94.5)`（95） | 统一为「折扣额按分四舍五入（半分进位），折后价 = 原价 − 折扣额」，前后端都用整数运算（`discounted_price` / `discountedPrice`），两边跑同一组用例 |
| 6 | 会话存储降级到内存后丢历史 | 成立 | 正式模式（`DEMO_LOGIN=false`）下 Postgres 会话存储不可用就拒绝启动；`/health` 增加 `persistent`，退回内存时 `status=degraded` |
| 7 | 发布流水线没有测试门槛 | 成立，三点都对 | 加 `test-core`（带 pgvector 数据库，先确认库可连，否则 DB 用例会 skip 成「假绿」）、`test-gateway`、`test-web`，构建依赖它们；`concurrency` 串行部署；服务器 `git reset --hard $SHA`，和镜像同一个提交；部署后轮询 `/health` 要求 `status=ok` |
| 8 | 账号校验失败时接受旧权限 | 成立 | 正式模式下查不到账号状态返回 50301（新错误码，已写进开发规范 §8.2）；演示模式保持原来的降级 |

## 线上排查（只读）
- 本机访问 `crm.jaxson.bond` 时，curl、PowerShell、内置浏览器都在 TLS 握手阶段断开，分不清是本机网络还是服务器的问题。改看 GitHub Actions 的部署日志。
- **发现问题**：最近一次部署（d24ca5f）后，`gateway` 容器没有重建。它的 IMAGE 一栏是 `sha256:5f75…`，说明 `salespilot-gateway:latest` 标签已指向新镜像，但容器还在跑 11 小时前的旧镜像，部署却显示成功。原因没法在服务器上直接确认。部署脚本已加兜底：`up -d` 后逐个比对容器实际镜像 ID 和本次镜像，不一致就 `--force-recreate`，仍不一致就让部署失败。

## 校验与兜底
- **审查的建议没有全部照做**：
  - 第 3 条重复流水号只做了「拦下并提示核查」，没有做「仍要登记」的二次确认。真遇到同号的另一笔，在流水号后加后缀即可。
  - 第 6 条没做「自动切回 Postgres」：内存里的会话切过去也接不上，改为正式模式不允许启动、演示模式在 `/health` 标出来。
- **回归测试先在旧代码上跑过**：报价幂等键（同会话同价确认两次拿到同一个键）、单号并发（两个事务同时取号拿到同一个号）都在旧实现上失败，新实现通过。
- **这次 Bash heredoc 里的中文被按 GBK 解码**，脚本断言失败、没有写坏文件；之后改为把非 ASCII 字符转义后写入，或者用 Edit 工具。
- **改了 1 个旧测试**：`test_software_quote_terms_follow_pack` 原来先提交审批、再直接改库里的行业包，然后看条款。现在条款在提交时固化，所以改成先改包再提交。真实业务里报价提交后不会换行业包。
- **`quote_service.py` 早已超过 400 行**，这次的快照逻辑放进新文件 `quote_snapshot.py`，没有继续往里加。
- 浏览器端到端测试仍没跑：本地 `.env` 开着企业微信推送，测试的启动检查会拒绝运行，避免把测试数据推到真实的群。
