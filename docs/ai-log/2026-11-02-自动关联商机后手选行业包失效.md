# 自动关联商机后手选行业包失效：要做小程序却一直问采购电脑人数

- 日期：2026-11-02 · 开发者：Claude Code · 模块：core（AI 工作台 Agent）
- 上一份：`2026-11-02-部署中途超时导致502.md`

## 任务卡
- **背景**：外部 Agent 自动化测试反馈：要求开发微信小程序，AI 却反复询问采购电脑的人数；明确纠正、手动选择「软件外包」之后仍然无效。手动测试时没有复现。
- **做法**：先在代码里找出两种走法的差别，写测试复现，再修复。

## 核实结果：问题存在，触发条件和手动测试不同
- 手动测试一般是**先选行业包再发消息**。这种情况在 `test_chosen_pack_wins_over_auto_linked_opportunity` 里已经修过，所以手动没有复现。
- 自动化测试是**第一句话没选行业包**，提到的客户（例如星河设计工作室）恰好只有一个进行中的「企业办公 IT」商机：
  - 出方案时会自动关联这个商机，`opportunity_id` 写进会话状态，于是按电脑采购追问人数。
  - 第二轮纠正并手选「软件外包」后，`prepare_chat._set_pack` 和 `choose_pack` 都把会话里的 `opportunity_id` 当成「从商机进入」，「商机产品线为准」，手选被忽略，继续问电脑人数。
  - 上一个行业包的需求草稿和追问字段也会带进下一轮。
- 加的回归测试 `test_choice_after_auto_link_switches_pack` 在修复前失败，修复前第二轮的 `pack_id` 仍是 `it_office`。

## 修改
- 新增会话状态 `opportunity_auto`，区分「出方案时按客户自动关联的商机」和「从商机详情进入」：
  - 自动关联时记为 True；从商机进入时记为 False。
  - 从商机进入时，仍然以商机产品线为准，这条规则不变。
- 后面几轮手选了和自动关联商机不同的行业包时，按手选的行业包作为新项目处理，取消关联那个商机，回复开头说明原因。这和第一轮就手选时的处理一致。
- 行业包换了以后，清掉上一个行业包的需求草稿、追问字段、校验结果和「已确认」，不再接着问电脑人数。

## 没有处理的
- 用户只用文字纠正（例如「不是电脑采购，是软件开发」）、没有手选行业包时，仍然沿用自动关联的商机。系统提示词会让模型确认当前按哪个行业包处理，并提示用户改选。系统不会根据文字自动切换行业包，因为自动切换可能误判，误判后的后果是关联到错误的商机。
