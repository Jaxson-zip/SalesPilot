# 输单后审批建议和收益过期、漏斗失败显示 0、新建表单没有未保存保护

- 日期：2026-11-02 · 开发者：Claude Code · 模块：core（审批、商机收益、迁移）、web（审批行、商机抽屉、工作台漏斗、表单侧栏）
- 上一份：`2026-11-02-三角色逐页逐弹窗检查.md`

## 任务卡
- **背景**：外部复测提了 4 个问题：
  1. 明理律所的商机已输单，报销审批仍写着「处于方案报价阶段，超标幅度可接受」；
  2. 输单、赢率 0% 的项目仍显示「实际赚 ¥42」，关联报价还显示「已审批」和发送入口；
  3. 模拟接口失败后，销售漏斗全部显示 0，旁边却显示进行中商机 1 个；
  4. 新建客户填了资料按 Esc，表单直接关闭，内容丢失。
- **做法**：先逐条对照代码核实（4 条都属实），再修复，每条补回归测试。

## 核实结果与原因
| # | 原因 |
|---|---|
| 1 | 审批建议在提交时生成、存进审批单，之后不会更新。明理律所那条是演示数据里写死的文字。界面只写「审批建议」，看不出是提交时的判断 |
| 2 | `deal_profit` 不看商机阶段，输单后照样按最新报价算毛利和提成；前端不管是否成交都叫「实际赚」。<br>报价：现在输单会关闭报价，后端发送前也有 `ensure_deal_open` 拦截，所以发送会被拦下。复测看到「已审批」，是因为这个商机在输单收尾功能（8dda11e）上线前就输单了，当时没有补处理旧数据，按钮看得见、点了才报错 |
| 3 | 工作台接口失败时，统计卡换成了错误提示，但漏斗拿到的是空数据，被当成每个阶段 0。旁边的「进行中 1 个」来自另一个单独请求的商机概览，它成功了 |
| 4 | 新建表单共用 `FormSheet`，没有「有未保存内容」的判断，Esc、点遮罩、点 ✕ 都直接关闭。不只客户，商机、联系人、报销、竞品战卡、回款计划都一样 |

## 修改
1. **审批建议**：
   - `approval_hints.deal_notes` 按审批单关联的商机实时给出当前状态，审批列表新增 `deal_note`：
     - 进行中：「关联商机「…」当前处于方案报价阶段」；
     - 输单 / 赢单：「…已于 11-02 输单，审批建议是提交时的判断」。
   - 前端改名为「提交时的审批建议」，下面一行显示 `deal_note`。AI 查待审批时也会带上它。
2. **输单收益**：
   - `deal_profit` 新增 `basis="lost"`：报价毛利、提成记 0，只算已经花掉的跟单费用，`net = −费用`。前端这种情况只显示跟单费用，合计叫「输单支出」。
   - 口径改名：按成交报价算的叫「实际赚」，还没成交按最新报价估算的叫「预计赚」。
   - 收益计算挪到新文件 `opportunity_profit.py`（`opportunity_service.py` 396 行，再加就超 400）。
   - 迁移 `0030_close_lost_quotes`：按 `close_lost` 的口径补处理旧数据：已输单商机下进行中的报价改为已关闭，待审批的报价审批单驳回，未完成待办标记完成。
3. **漏斗**：`FunnelChart` 新增 `onRetry`，工作台接口失败时显示「漏斗数据暂不可用」和重试按钮，不再画 0。
4. **未保存保护**：
   - `FormSheet` 新增 `dirty`：有未保存内容时，Esc、点遮罩、点 ✕ 先弹「放弃没保存的内容？」。底部「取消」是明确放弃，不再问。
   - 6 个表单都接上了：新建客户、新建商机、联系人、报销（新建和修改）、竞品战卡、回款计划编辑。
   - 判断用 `lib/form-dirty.ts` 的 `changedFrom`：和打开时的内容比，只改了首尾空白不算修改。

## 校验与兜底
- **我自己写错的一处**：第一版测试想直接新建「方案报价」阶段的商机，新建接口不接受阶段参数，断言失败。改成按默认的「线索」阶段断言。
- **我自己写错的另一处**：用 Python 脚本往竞品表单里写 `join("\n")` 时，转义被吃掉，写进去的是真的换行，eslint 报「字符串未结束」。已改正。
- 迁移的测试不经过 alembic：模拟修复前的输单（只改阶段、不收尾），直接执行迁移里的语句，再检查报价、审批单、待办都被处理了。
