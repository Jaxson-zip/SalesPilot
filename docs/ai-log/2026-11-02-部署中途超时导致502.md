# 部署中途超时导致线上 502：拉镜像和切换容器拆成两步

- 日期：2026-11-02 · 开发者：Claude Code · 模块：CI/CD（`.github/workflows/deploy.yml`）
- 上一份：`2026-11-02-复测流程断点修复.md`

## 任务卡
- **背景**：推送 8dda11e 后线上返回「服务不可用（HTTP 502），请确认 core 已启动」。
- **做法**：先看 CD 日志定位原因，重跑部署恢复线上，再改部署流程，避免同样的问题再出现。

## 原因
- 测试和构建都通过了，失败的是 deploy 这一步。
- 服务器从 ghcr 拉镜像特别慢：core 有一层卡了约 19 分钟，gateway 有一层卡了约 20 分钟。
- 原来拉镜像和 `docker compose up -d` 在同一条 SSH 命令里，共用 40 分钟超时。拉完镜像时间就用光了，超时时正在执行 `Container salespilot-core-1 Recreate`，命令被直接中断。旧容器已经删掉，新容器没有启动，nginx 返回 502。
- 和这次的业务改动无关，迁移 0029 也没问题。重跑部署后，镜像已经在本地，30 秒内完成，core 健康检查返回 ok。

## 修改
- 拆成两个 SSH 步骤，分别计时：
  - **Pull images on server**（60 分钟）：只登录 ghcr 拉镜像，不动正在跑的容器。三个镜像并行拉，单个失败重试 3 次。这一步超时或失败，线上还是旧版本；重跑时已经下载的层会复用。
  - **Switch containers on server**（15 分钟）：先确认三个镜像都在本地，缺一个就不动线上。然后依次对齐代码、打标签、`up -d`、核对镜像、迁移和就绪检查，和原来的逻辑一样。
- 原来的保护都保留：拉取失败不吞掉、核对容器跑的是本次镜像、就绪检查失败时打印 core 日志。

## 校验与兜底
- 用 PyYAML 解析工作流，两段脚本都过了 `bash -n` 语法检查。
- 用假 `docker` 模拟 web 镜像拉取连续失败：三次重试后整个脚本退出码为 1，不会进入切换容器那一步。
- 没有在真实服务器上跑过新流程，下一次推送时才会验证。
