# 回款计划锁定与合同列表口径

- 日期：2026-11-03 · 开发者：Claude Code · 模块：core（回款计划、合同列表）、web（回款计划侧栏、合同页）
- 上一份：`2026-11-03-数据同步问题修复.md`

## 任务卡
- **背景**：用户贴来一份合同 / 回款页面的审查意见，共 6 条，让我判断是否合理，有问题就改。
- **做法**：逐条对照代码核实，再决定改不改、改多少。

## 逐条判断

1. **（高）有回款、有发票的合同仍能随意调整计划**：成立，而且后端也有漏洞。
   - 原来后端只拦「已开票的期次改金额」。已收齐、收过一部分的期次都能删、能改金额和到期日，已收的钱冲抵到哪一期会跟着变。逾期的期次直接改到期日，逾期就消失了。
   - 改动记录只留了新计划，没有原计划，也没有原因。
2. **（高）回款按期次顺序冲抵，系统分配不等于客户实际付的期次**：部分成立。
   - 按期次顺序冲抵是既定规则（与财务核销顺序一致），这次不改。
   - 「允许按凭证手工调整归属」要给每笔到账加上期次归属，这是数据模型级别的改动，这次没做。
   - 实际改了表述：表头「已到账」改为「已冲抵」，说明文字写明这是系统分配，每笔实际到账看回款记录。迁移前的回款在迁移时补过一条「迁移前登记」的汇总记录（`0026_payments`），没有更细的明细。
3. **（中）已回款的合同仍有未开票的期次**：成立。列表原来只提示「已申请、等主管登记」。
4. **（中）提成「¥15,120 / ¥37,800」看不懂**：成立。只有鼠标悬停时才有提示。系统不管发放，所以不加「已发放」。
5. **（中）顶部卡片时间口径混在一起**：成立。三张卡片只有第一张按本月；三张都不受页签和筛选影响，页面上没有写。
6. **（中）列表「下期回款 ¥405,000」与详情 ¥486,000 对不上**：成立。列表显示的是本期还差的金额，名称却叫「下期」，而且这一期可能已经逾期。

## 修改
- core：新增 `payment_plan_change.py`，`replace_payment_plan` 从 `contract_service` 移到这里（`contract_service` 原来 397 行，接近 400 行的上限）。规则如下：
  - 已收齐的期次：不能删除，不能改金额和到期日（`plan_paid_locked`）；
  - 收了一部分的期次：不能删除，金额不能低于已收（`plan_paid_locked`）；
  - 已申请或已开票的期次：保持原规则（`plan_invoiced`）；
  - 合同已有回款、逾期或开票时，必须填写原因（`plan_reason_required`）；
  - 动态里记录「原计划 / 新计划 / 原因」。
  - 前面的期次锁定后，已收的钱冲抵到哪一期就不会再变。
- 接口：
  - `PaymentPlanUpdate.reason`；
  - `NextPayment.plan_amount`（本期总额）；
  - `ContractItem.invoice_pending`（已收过款或已到期、还没申请开票的期数）。
  - AI 工具 `list_contracts` 的当前应收补上「还差」和「本期总额」，避免 AI 也把两个数说混。
- web：
  - 编辑器拆成 `PlanEditor.tsx`。已收齐的期次只显示，不给输入框；收了一部分或已开票的期次不给删除按钮，并说明原因；需要写原因时显示「调整原因」。所有期次都收齐时，不显示「调整计划」按钮。
  - 合同列表：
    - 「下期回款」改名「当前应收」，显示「第二期 待收 ¥405,000」；收过一部分时加一行「本期 ¥486,000 · 已收 ¥81,000」；
    - 新增「待开票 N 期」标签，原来的「待开票」标签改名「开票申请中」；
    - 提成列名改为「提成 已确认/预估」。
  - 顶部卡片：第一张注明「本月新签合同金额」，另外两张标「全部合同」，并注明不受筛选影响。
- 没做：变更审批（第 1 条建议里的「审批记录」）、按凭证手工调整到账归属（第 2 条）。这两项都要新增流程或数据结构，需要用户决定后再做。

## 校验与兜底
- 加了「有回款 / 开票就必须写原因」之后，原有的两个用例失败了：`test_invoice_request_issue_void_and_unpaid` 和并发用例 `test_plan_change_does_not_overwrite_concurrent_invoice`。原因是它们给已开票的合同调整计划时没带原因，这正是新规则要拦的情况。给这两个用例补上原因后通过。
- 浏览器测试 `v6.spec.ts` 原来改的是第 1 期的金额，而 C-2026-001 的第 1 期已经收齐、被锁定，所以改成改第 3 期，同时检查第 1 期没有输入框、页面要求填写调整原因。

- 在本地页面上检查时发现，回款计划侧栏比较窄，原来的「名称 / 金额 / 到期日」三栏挤在一行，期次名称只剩一个字（锁定行显示成「预」）。这个问题原来就有，锁定行让它更明显。改成名称单独一行，金额和到期日放在第二行。
