# 实测 6 个问题与同类问题自查

- 日期：2026-11-03 · 开发者：Claude Code · 模块：web（请求层、跟进、报销、报价、日报）、core（跟进时间、报价推进商机、日报统计）
- 上一份：`2026-11-03-回款计划与合同口径.md`

## 任务卡
- **背景**：用户实测又发现 6 个问题，并指出「怎么老是提出新的问题」，要求我站在使用者和开发者两个角度自己完整查一遍。
- **做法**：
  - 每个问题先找到根因；
  - 能统一修的就在公共层修，不在单个按钮上打补丁；
  - 再按同一类原因查其他页面。

## 问题、根因与修改

1. **快速双击生成两张相同的报价。**
   - 根因：按钮在 `isPending` 变成 true 之前就收到了两次点击，两个请求都发出去了。另外，创建成功到页面跳转之间，按钮又能点了。
   - 修改（公共层）：`lib/api.ts` 的 `apiFetch` 对写请求去重。同一个写请求（方法、地址、请求体都相同）在第一次返回之前不会再发，所有按钮都受益。新建报价页在创建成功、跳转之前保持「保存中」。
2. **刚保存的跟进显示「15 小时前」。**
   - 根因：前端把日期拼成 `YYYY-MM-DDT00:00:00`，不带时区，后端按 UTC 零点存。
   - 修改：
     - 前端新增 `followupOccurredAt`：选今天就不传，后端记为保存时间；补记往日的跟进，取那天的此刻，并带时区。
     - 后端新增 `PastTime`：不带时区的时间按北京时间理解，不能晚于现在。`PlanTime`（任务截止时间）也改成不带时区时按北京时间理解。
3. **多行跟进显示成一行。**
   - 修改：时间线加 `whitespace-pre-wrap`。
   - 自查：审批意见、触发原因、报价动态、报销事由、驳回原因这几处同样会显示用户写的多行文字，都改成保留换行。
4. **从客户招待切到住宿后，仍提示客户招待的必填项。**
   - 根因有两个：
     - 表单错误只在提交时更新，改了字段也不清掉；
     - 实时制度校验用了 `keepPreviousData`，新结果回来之前一直显示旧类型的结果。
   - 修改：新增 `clearError`，改哪项清哪项的错误，换类型时全部清掉；校验结果是旧数据时不显示。
5. **报价只保存了草稿，商机赢率就从 10% 升到 50%。**
   - 根因：AI 生成报价、手工新建报价、草稿关联商机这三处都会立即把商机推进到「方案报价」。
   - 修改：推进统一放到「发送客户」时（`quote_revision.advance_deal`），动态里会写明「商机推进到方案报价」。处于谈判阶段的商机仍然不往回退。
   - 自查：`apply_stage` 的调用方只剩手动改阶段、发送报价、客户接受报价后赢单和标记赢单这四处。
6. **日报统计口径不清。**
   - 根因：
     - 统计按操作日志数「新建 + 提交」，同一张报价算两次；
     - 报价发出后的自动推进、AI 的推进没有经过阶段接口，所以没算进阶段推进；
     - 页面上没有说明怎么统计。
   - 修改：
     - 改为按业务数据统计：新建报价 = 当天新建的报价单张数；阶段推进 = 商机动态里的阶段变化，包含手动、AI 和自动推进；
     - 页面数字下方加一行口径说明，「报价」改名「新建报价」。

## 自查（同类原因逐项查）
- **重复提交**：已在请求层统一处理。报销、回款原来就有幂等键。AI 对话发送时会清空输入框，不会重复发送。
- **时间与时区**：前端发给后端的时间只有跟进拼了不带时区的字符串，任务截止时间用的是 `toISOString`，没有问题。后端接收时间的入参里，跟进和任务现在都把不带时区的时间按北京时间理解。
- **换行**：用户用多行输入框写的内容（跟进、审批意见、驳回原因、报销事由、日报）显示时都保留换行。动态流、列表摘要里本来就截成 1～2 行，不改。
- **表单残留**：只有报销会因为切换类型改变必填项，已修。其他表单的必填项是固定的，提交时会重新校验。
- **隐式状态变化**：只剩上面列出的四处会改商机阶段。

## 校验与兜底
- 让「发送客户才推进商机」后，有两个旧用例失败：`test_quote_moves_early_opportunity_to_proposal` 和 `test_create_quote_from_scratch`。它们按旧规则断言新建报价就推进商机。按新规则改为断言草稿不推进、发送后推进。
- 跑 prettier 时顺带改了 5 个与本次无关的文件的格式，已经还原，提交里只有本次的改动。

- 第一次跑全量测试时，`test_tasks_api.py::test_due_filters_and_dashboard` 失败了，单独跑能通过。核对时间后发现，那次运行正好跨过北京时间 0 点：开始时生成的「今天到期」演示任务，跑到这个用例时已经变成了昨天。相邻的用例原来就用 `tasks_for_today` 重写当天的任务，这个用例没有用，所以给它补上。第二次全量 776 个全部通过。
