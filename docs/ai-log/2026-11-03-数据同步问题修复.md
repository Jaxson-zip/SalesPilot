# 数据同步问题修复：一处变了，别处的同一份数据没跟着变

- 日期：2026-11-03 · 开发者：Claude Code · 模块：core（公海、成员、商机收尾、分享、通知、联系人）、web（分享页、确认文案）
- 上一份：`2026-11-03-待办加入回款日报审批.md`

## 任务卡
- **背景**：用户让我分别从使用者和代码的角度审查，重点看「记录删了或变了，别处还留着旧数据」这类不同步的问题。审查后列出 6 个问题，用户确认全部修复。
- **做法**：
  - 第 1 条先在测试库复现，其余按代码确认；
  - 每条修复都配一个回归测试，放在 `tests/api/test_data_sync_api.py`，共 9 个用例；
  - 关闭报价的逻辑抽成一处公共代码，输单、赢单、退回公海、被新版本替代共用。

## 问题与修改

1. **退回公海后，报价和待办变成没人负责。**
   - 原因：退回公海只检查有没有进行中的商机。测试库复现结果是：「已发送」的报价负责人变空、状态不变，未完成的任务负责人也变空。90 天无跟进自动退回走的是同一段代码。
   - 修改：在 `pool_service.close_open_work` 里，手动退回和自动退回都先做三件事：关闭没成交的报价、驳回待审批、把未完成的待办标为完成。处理结果追加到退回动态里，退回对话框的说明也同步更新。

2. **成员调团队，名下数据留在原团队。**
   - 原因：`update_account` 只改了人的团队。新主管看不到他的数据，他提交的审批仍然由原主管处理。
   - 修改：新增 `transfer_service.move_member_team`。名下客户（含联系人、跟进、进行中的商机、没成交的报价、未完成的任务、动态）跟着人走；没有关联客户的报价、还没处理完的报销单，以及它们的待审批也一起走。已成交的合同、回款计划和提成留在原团队，业绩仍算在原团队。

3. **赢单后，同一商机的其他报价还停在「已发送」。**
   - 修改：新增 `opportunity_close.close_won_siblings`。赢单时关闭同一商机下其他没成交的报价，已接受的那张不受影响。商机下的其他待办不动，赢单后还要签合同、对接交付。

4. **关闭或被拒绝的报价，分享链接仍然像有效报价。**
   - 修改：客户打开时页面显示「这份报价已失效」，不计打开次数，也不再提醒销售「客户在看报价」。
   - 链接本身没有撤销，客户打开后能看到失效原因，不会只看到一个报错页。

5. **事情处理完，铃铛里的提醒仍然是未读。**
   - 修改：`notification_service` 新增 `resolve_keys`、`resolve_tasks`、`resolve_approval` 三个函数，在下面这些时机把对应提醒标为已读：
     - 任务完成、删除或改期；
     - 待办被自动完成；
     - 审批通过或驳回，所有主管的「待审批」「催办」一起标已读；
     - 审批被自动驳回；
     - 回款收齐的期次；
     - 日报提交（保存草稿不算）。

6. **删除联系人后，重新编辑被驳回的报销单时参与人消失、人数被重算。**
   - 修改：联系人如果还在「草稿 / 待审批 / 被驳回」的报销单里，就拒绝删除，并提示是哪几张单子。已审批的报销单另存了参与人文字，不受影响。删除确认文案改成和实际行为一致。

## 校验与兜底
- 第一次用脚本批量改文件时，有两处替换没有匹配上，脚本在中途断言失败，结果只改了一部分。用 grep 核对后，剩下两处改为逐条手工修改。
- 查询数组字段时，`ARRAY.any()` 在 SQLAlchemy 2.1 里已经弃用，测试时出现了警告，改用 `any_()`。
- 抽出公共代码后，第一次跑全量测试有 1 个失败（`test_business_rules.py::test_lost_sets_reason_and_closed_at`）。原因是新代码用 `list(db.scalars(...))` 读查询结果，而单元测试里的假会话只支持 `.all()`。改回和原代码一致的 `.all()` 后通过。
- 竞品删除那段代码的注释写「商机上的标注不受影响」，实际行为是移除标注。页面上的提示是对的，这次只把注释改正。
