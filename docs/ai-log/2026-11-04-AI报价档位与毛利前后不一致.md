# AI 出方案：确认后档位显示错、回复引用作废的毛利

- 日期：2026-11-04 · 开发者：Claude Code · 模块：core（agent 出方案链路）、web（AI 工作台方案卡）
- 上一份：`2026-11-04-销售视角全流程走查.md`

## 任务卡
- **背景**：用户在线上 AI 工作台给明理律所出方案。确认卡写着「方案 标准版 · 毛利 29.4%」，生成的报价单 Q-2026-008 却是经济版 ¥188,160。AI 接着说「更正上一轮：经济版毛利是 21.8%，低于 25%」，可报价卡上写的是 25.1%。用户问：是行业包的问题还是 agent 的问题？
- **做法**：先查线上数据，确认实际发生了什么，再改代码。查询只读，用的是 SSH 免密登录。

## 查到的事实（线上数据库）
- Q-2026-008：草稿，¥188,160，毛利 25.06%，幂等键 `agent:t_mw1nuesk_4:…`。
- 这个会话的 checkpoint：
  - 确认请求带的是 `{"decision":"approve","tier":"economy"}`，也就是点确认时卡片上选中的是经济版，报价单按经济版生成是对的；
  - 第一次毛利校验的结果是「economy 毛利 21.8% < 25%」，于是回到配置重做；第二次「全部档位毛利达标」，经济版重配后是 25.1%。
- 结论：行业包的配置和规则计算都没错，报价金额、毛利也没算错。错在两处显示和回复。

## 问题、根因与修改
1. **确认后，方案卡和确认卡回到推荐的标准版。**
   - 根因：点确认时，前端清掉了本机草稿（销售另选的档位），卡片于是按推荐档显示。物料清单也仍是 `price` 节点推的推荐档。
   - 修改：
     - core：`save_quote` 生成报价单后，重新推送实际生成档位的物料清单（含调整后的数量）；新增 state `saved_tier`，会话历史里的物料清单也按它保存；
     - web：新增 `savedTierOf`。报价单推回之前，用点确认时卡片上的档位；推回之后以后端的物料清单为准。方案卡的选中状态、确认卡、物料清单都跟着它，打开历史会话也一样。
   - 回复模板写明生成的是哪一档：「报价单 Q-… （经济版）已创建」。原来模型看不出销售另选了档位，会说「金额不是推荐的标准版」。
2. **回复引用了作废的毛利。**
   - 根因：`tool_log` 把两次毛利校验都交给了回复模型，第一次（21.8% 不达标）已经被重配取代，模型却拿它「更正」数字。
   - 修改：`log_tool` 遇到会重做的步骤（配置方案、毛利校验）时，用新结果取代旧结果。
- 回归测试：
  - core `tests/unit/test_agent.py`：
    - `test_approve_with_another_tier` 断言物料清单是经济版、回复里写着经济版；
    - 新增 `test_retried_margin_check_replaces_earlier_result`。
  - web `artifacts.test.ts`：`savedTierOf`。

## 校验与兜底
- 用户问「是不是所有流程都过了一遍」。如实说明：上一轮走查没有在页面上点 AI 工作台，这个问题正是在没点到的地方。这次在本地补了 AI 出方案 → 另选档位 → 生成报价单的点击检查（见下）。
- `test_approve_with_another_tier` 原来取「第一个 artifact」当作报价单；现在生成后先推物料清单，改成按类型取。
