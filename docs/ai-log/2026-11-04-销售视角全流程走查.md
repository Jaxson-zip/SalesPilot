## 任务卡
- **背景**：用户要求把审查范围扩到整个项目，站在销售的角度模拟真实使用，找出数据对不上、流程出错的地方。
- **做法**：在本地以销售张晨的身份，从头走一遍真实业务。每一步都核对页面上显示的数字，和接口、数据库里的数据是否一致。
  - 完整走了一遍：新建客户 → 联系人 → 商机 → 手工报价（双击）→ 提交 → 发送 → 客户接受 → 合同 → 申请开票 → 报销 → 任务 → 日报。
  - 再切到主管李薇，看团队数据和审批。

## 走查结果（逐项核对）
- 新建客户：重名检查生效。
- 报价：
  - 双击「创建」只发出 1 个请求；
  - 草稿和提交都不推进商机，发送后商机推进到方案报价（50%），客户接受后赢单（100%）；
  - 商机金额同步为报价金额 ¥262,000。
- 合同：
  - 合同金额、预估提成 ¥3,930 和报价一致，回款计划 30 / 60 / 10；
  - 合同列表顶部的预估提成（¥91,530）、已确认提成（¥39,930）、待回款（¥1,306,000）三项，都等于列表各行逐项相加；
  - 申请开票后，该期显示「已申请 · 专票」，开票历史里记了一条。
- 待办：工作台待办里有「催回款：C-2026-006 预付款 今天到期」。
- 任务：发送报价时自动生成跟进任务，客户接受报价后自动完成，备注「客户已接受报价，自动完成」。
- 报销：没传发票时提交被拦下（`expense_missing_invoice`）；传了发票后，制度校验通过，直接通过。
- 主管视角：团队本月成交 ¥354,000；待审批 3 条报销，超标金额核对正确。团队日报里张晨当天的数字是：新建报价 1、阶段推进 2、完成任务 1，和走查时的实际操作一致。

## 发现的问题与修改
1. **个人模式下，提示文案与实际行为不符。**
   - 现象：本地开着个人模式，超出折扣权限的报价提交后直接通过；但页面写着「需主管审批」，报销确认框也写着「超标的进入主管审批」。
   - 修改：`confirm-texts.ts` 新增 `expenseSubmitConfirm(solo)`、`quoteApprovalHint`、`quoteDraftRule`、`expenseOverTitle`。报销确认框、报销超标提示、报价审批提示、报价规则提示都改成按个人模式区分说法。
   - 回归测试：`stage-move.test.ts`。
2. **前端用浏览器时区算「今天」，后端用北京时间，海外时区下两边差一天。**
   - 现象：本机是太平洋时间。北京时间 11-04 凌晨，日报页查的仍是 11-03，所以当天新建的报价和推进都显示 0；同一时刻主管看团队日报（11-04）数字是对的。任务的「今天 / 明天」快捷选项、到期文案、报销和回款的日期默认值、上限，用的也是浏览器日期。
   - 根因：`localDate()` 取的是浏览器时区的年月日；`dueShortcutDate`、`dueDayLabel` 用本地零点计算；`toDueIso` 把输入的钟点按浏览器时区理解。
   - 修改：
     - `lib/format.ts`：
       - `localDate` 改为按北京时间取日期（中国没有夏令时，固定 +8）；
       - 新增 `localClock`、`addDays`、`daysBetween`、`beijingInstant`；
       - 补记往日跟进时，取那天北京时间的此刻。
     - `lib/tasks.ts`：快捷选项、到期文案、输入时间都按北京时间。
     - `ReportParts.localDate` 不再自己算，改用上面的工具。
   - 只显示时间戳的地方（审计日志、对话历史、「提交于 HH:mm」）仍按浏览器本地时间显示，不改。
   - 回归测试：
     - `format.test.ts`：太平洋时间 11-03 08:35 → 11-04；UTC 16:00 前后的分界；跨月、跨年加减天数；
     - `tasks.test.ts`：太平洋时间早上的「今天 / 明天」、到期文案和输入时间。
   - 原来的用例用 `new Date(年, 月, 日)` 按运行环境时区构造时间，结果随运行环境变化。现在全部改成带 `+08:00` 的时刻；在太平洋、北京、东京、UTC 四个时区分别跑，383 个都通过。

## 第二轮：在页面上逐步点击（用户追问「是不是真的模拟了点击」）
- 用户指出：第一轮有不少步骤（报销、主管视角、合同数据）是在浏览器里直接调接口完成的，不是在页面上点出来的。这一轮补上在页面上点击，并重点看销售用起来是否顺手。
- 点击走查的内容：
  - 客户详情：写跟进、添加下一步（「明天」默认 11-05，北京时间正确）；
  - 看板：新建商机；
  - 新建报价页；
  - 手机宽度下的看板。

3. **客户时间线看不到这个客户的成交过程。**
   - 现象：报价发出、客户接受、赢单、开票都发生了，客户详情的时间线却只有「创建了客户」「添加了联系人」。
   - 根因：`list_activities` 只查 `subject_type=customer` 的动态。
   - 修改：`/api/activities` 新增参数 `related`。客户时间线会同时带上这个客户名下商机（创建、阶段变化）、报价（发送、查看、接受、拒绝）、合同（回款、冲正、开票）的里程碑；改字段、提交审批这类内部步骤不显示。前端在动作后面注明是哪一单，如「发送了报价单 · Q-2026-013」。
   - 回归测试：`test_customer_timeline_api.py`、`timeline.test.ts`。
4. **新建商机时，客户还没建（用户实测提出）。**
   - 现象：只能关掉表单去客户页新建客户，已经填好的商机内容全部丢失。
   - 修改：在公共的 `CustomerCombobox` 列表底部常驻「新建客户「输入的名称」」：
     - 点击后弹出新建客户表单，名称已预填，原有的重名检查照常生效；
     - 建好后自动选中这个客户，回到原表单，已填内容保留；
     - 没有新建客户权限的角色不显示这个入口；
     - 新建商机、新建报价、报销、报价关联客户这四处都用这个组件，所以一起生效。
   - 回归测试：`customer.test.ts`。
5. **客户详情的「报价单」页签没有新建入口。**
   - 现象：页签里只写着「该客户还没有报价单」；新建报价页也只能从商机带入客户。
   - 修改：
     - 空状态加「新建报价」按钮，只有负责人看得到；
     - 新建报价页支持 `?customer=`，自动带入客户；
     - 客户只有一个进行中的商机时自动关联这个商机（`defaultQuoteOpportunity`），销售手动改过就不再覆盖。
   - 回归测试：`links.test.ts`、`quote-actions.test.ts`。
6. **写跟进时不能选联系人和商机（走查后用户确认要加）。**
   - 现象：时间线上只有「记录了电话」，看不出打给了谁、是哪一单的事；商机详情按商机筛跟进，但手工写的跟进从来不带商机。
   - 修改：
     - core：`followups` 新增 `contact_id`（迁移 `0031_followup_contact`，联系人删除后置空，跟进保留）；写跟进时校验联系人属于该客户（40001）；列表一次查出商机名、联系人名返回。
     - web：写跟进的工具行加「联系人」「关联商机」两个选择框，没有联系人 / 商机时不显示；客户只有一个进行中的商机时默认选上；保存后保留选择，方便连续记同一单；时间线显示为「记录了电话 · 王律师 · 私有化部署」。
   - 回归测试：`test_misc_api.py`（`test_followup_records_contact_and_deal`、`test_followup_contact_must_match_customer`）、`timeline.test.ts`（`followupAction`）。
- 点击确认：
  - 搜索「走查新建物流」→ 显示「没有匹配的客户」和「新建客户「走查新建物流」」→ 点击后名称已预填 → 创建 → 回到新建商机表单，客户已选中，之前填的商机名称还在；
  - 客户时间线按时间完整显示了从商机创建到开票申请的过程；
  - 从客户「报价单」页签点「新建报价」，客户自动带入。
  - 写跟进：选联系人「走查李经理」和商机「走查私有化部署」后保存，时间线显示「记录了电话 · 走查李经理 · 走查私有化部署」，选择框保留原值；该客户唯一的商机已赢单，所以商机默认是「不关联商机」，符合规则。core 全量 779 个、web vitest 389 个通过。

## 校验与兜底（AI 自己的失误）
- **走查时触发了一次真实的企业微信推送。** 本地 `.env` 配置了企业微信 Webhook，「赢单喜报」事件也是开着的。我在走查中点了「客户接受」，商机随之赢单，`opportunity_close.push_won` 向群里发了一条「赢单：走查私有化部署」（推送记录显示 16:32 UTC 发送成功）。这违反了「本地测试不触发企业微信推送」的约束。
  - 发现后的处理：逐个确认了所有推送入口：
    - 赢单喜报；
    - 报价或报销进入审批（个人模式下不会创建审批，所以不推送）；
    - 回款逾期、日报催交两个定时任务；
    - 推送日报汇总。
  - 之后的走查避开了赢单、推送日报汇总和审批。
  - 后续避免：本地走查前先在「设置 → 集成」关闭推送，或把本地的 Webhook 置空。
- 判断为**不是问题**、没有改动的：
  - 合同列表写「11-04 到期」，待办写「今天到期」：时区不同造成的，北京时间当天就是 11-04；
  - 单独报 GPU 服务器、按目录价报价时毛利低于底线：毛利按整单算，硬件本身毛利 12.5%～17%，配上服务的方案能达标，只报硬件需要主管审批，符合规则；
  - 日报团队成员行在没有内容时不能展开：这一行没有箭头、鼠标也不变成手形，不属于「看得见却点不了」的按钮。
- 还没处理、留给用户决定的：商机金额在赢单之前不会跟着已发送报价的金额变（¥300,000 对 ¥262,000），只有客户接受报价后才同步。
