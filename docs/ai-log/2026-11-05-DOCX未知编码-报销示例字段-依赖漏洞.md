## 处理
| 问题 | 根因 | 处理 |
|---|---|---|
| DOCX `encoding="xyz-unknown"` → 500 | `docx_text` 靠手工列举的异常元组 `_DOCX_ERRORS` 兜底，`ElementTree` 遇到未知编码抛 `LookupError`，不在元组里。这是**第二次**因为漏列异常类型出 500（上一轮漏了 `RuntimeError` / `NotImplementedError`） | 不再列举：解析阶段 `except BizError: raise`，其余**任何异常**都按「文件无法读取」返回 40001，并在日志记录异常类型（`docx unreadable: LookupError`），方便发现新的坏文件类型。删除 `_DOCX_ERRORS` |
| 报销预检示例按 1 人计算 | ①上一轮抓样本时凭印象写字段名；②`ExpensePrecheckIn` 不拒绝未知字段，错字段名照样 200，`headcount` 取默认 1——返回里「人均 = 总额」本该一眼看出不对，但没核对 | 按 `ExpensePrecheckIn` 重新在 :8080 抓样本：4 人 1860 元 → 人均 465、超出 1260；补字段说明和「未知字段会被忽略」的提示；第四节 curl 示例同步改。其余请求示例（客户、阶段、对话）逐个对过 schema，无误 |
| pypdf 6.21.2（7 个 CVE，修复版 6.21.3 / 6.21.4） | — | `uv lock --upgrade-package pypdf` → 6.21.4 |
| filelock 3.32.7（13 个 CVE，只在 4.x 修复） | litellm（含最新 1.108.0）声明 `filelock<4.0`，正常升级解不出来 | 查了引用方：litellm 只在 proxy CLI 里用（网关不用），huggingface_hub 用 `FileLock` / `SoftFileLock` / `BaseFileLock` / `Timeout`，4.x 仍兼容。在 `[tool.uv]` 加 `override-dependencies = ["filelock>=4.2.1"]` → 4.2.9，注释写明原因和何时删 |
| next 自带 postcss 8.4.31（2 high + 2 moderate） | next 15 把 postcss 锁死在 8.4.31 | `pnpm-workspace.yaml` 加 `overrides: postcss: ^8.5.31`（同一大版本，项目其他地方本来就用 8.5.31） |

### 为什么不给预检接口加 `extra="forbid"`
本想让错字段直接报 40001，查调用方发现前端 `useExpensePrecheck` 把整张报销草稿（`ExpenseCreate`，含客户、事由、参与人等）直接发给预检。加了会让报销表单的实时校验全部失败。改为在文档里写明这一点。

| 上一轮接口文档的报销示例字段名错（`category` / `attendees`） | 抓样本时没查 schema，凭印象写；返回「人均 1860 = 总额」没核对就写进文档 | 按 schema 重抓；以后示例写完要用一句话核对数字（4 人 1860 → 人均 465） |
