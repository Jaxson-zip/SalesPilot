# 报销体验反馈五项：删草稿、取消前提示、审批进度、「其他」类说明、票据未验真

- 日期：2026-11-05 · 开发者：Claude Code · 模块：core（expense_service、quote_query、rule_notes、templates.yaml）、web（报销抽屉、审批记录）
- 上一份：`2026-11-05-两个团队演示账号与全流程走查.md`
- 约束：不新建表、不新建页面；能复用的组件就复用。

## 任务卡
试用者反馈的五个问题：
| 问题 | 处理 |
|---|---|
| 草稿无法自行清理 | 新增 `DELETE /api/expenses/{id}`：只有从未提交过的草稿能删，票据文件一起删；已提交、被驳回的有审批记录，返回 42201。抽屉底部加「删除草稿」（仅草稿显示），确认后删除 |
| 未保存内容点取消就丢 | 原来只有 Esc / 遮罩 / ✕ 会提醒，底部「取消」「取消修改」直接丢弃。现在一律提醒，并多一个「保存草稿 / 保存修改」选项（ConfirmAction 支持第三个按钮） |
| 审批进度不透明 | 审批记录增加 `submitted_at`（提交时间）和 `handler`（待审批时由谁处理 = 团队主管）。新组件 `ApprovalTrail` 显示：状态、正在处理 / 已处理的人、提交时间、触发原因、审批意见；报价单和报销单共用 |
| 「其他费用」写着实报实销，¥0.01 也要审批 | 原来规则说明把「交通、其他：实报实销」写在一起，但规则代码里「其他」类本来就是每笔都审批。拆成两行，「其他费用：没有标准，每笔都需主管审批」，报销须知同步 |
| 票据校验只认类型 | 票据列表下注明「已上传 ≠ 已验真：只检查文件格式和票据类型，不核验发票真伪；主管审批时会逐张核对」。没有接发票查验接口（需要税务平台账号，演示环境做不了，也不假装做了） |

## 发现的问题与人工修正
| 问题 | 原因 | 修正方式 |
|---|---|---|
| 「其他」类说明和实际行为不一致 | 早期 AI 写规则说明时把交通和其他合并成一行，没对照 `check_expense_policy` | 拆开写，并加测试锁住说明文字 |
| 新测试里按 `target_id` 查附件，字段不存在 | AI 把 Approval 的字段名套到了 Attachment 上（实际是 `owner_ref_id`） | 改正字段名 |
| 浏览器走查时发现「其他」类 ¥0.01 草稿的提示框标题仍只写「需主管审批」 | 改了规则说明，但提示框标题 `expenseOverTitle` 在没超标时只有四个字 | 改为「制度里没有标准，不论金额大小都需主管审批」，补 Vitest 回归用例 |
| 线上验收时发现「其他」类提示的依据写成「4.2 招待标准」 | `check_expense_policy` 对「其他」类沿用了招待标准的 `rule_ref` | 改为只写《费用报销管理制度》（和报销须知一致），补单元测试 |
| 用户反馈：放弃提示框里「保存草稿」按钮白底白字看不见 | AI 用 `AlertDialogAction`（默认深色底白字）再叠 outline 样式，只换了底色，没覆盖文字颜色 | 改用本身就是描边样式的 `AlertDialogCancel`，本地浏览器确认文字可见 |
| 新组件放进报价页后留下没用的导入 | 把报价页的审批列表换成共用组件时，原来的导入没删 | lint 报警后删掉 |
