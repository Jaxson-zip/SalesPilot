## 逐条核实
| 报告的问题 | 核实结果 | 处理 |
|---|---|---|
| 学习问答「无法跳转」：失效会话静默显示默认「做方案」 | **属实**。按钮本身没问题。打开失效会话时只弹 4 秒通用提示「记录不存在或你无权查看」，地址里的 `?t=` 不去掉，页面看起来就是普通空白页 | 打不开（40401）时提示「这条会话打不开：可能已被删除、演示数据已重置，或不属于当前账号。已为你打开新对话」，同时把地址换成 `/ai` |
| 管理员可能一直显示「正在加载会话…」 | 本地三个角色都没复现，加载状态 1 秒内结束。线上更可能是静态脚本慢，导致页面没有完成水合 | 不改代码；静态资源见下 |
| P0：王磊 7 条报销变 0、原密码不能登录、旧 Bearer 仍能访问 | **报告用的是旧版本**。数据清空是上一轮在线上手动跑的 `seed --reset`；旧 token 不失效已在 36ebcbe 修复：Bearer 和 Cookie 都走 `token_version` 校验，改密码、管理员重置、seed 都会加一 | 不改；README 已写明线上有人试用时不要跑 `--reset` |
| P1：部分 AI 页面脚本冷请求 20 秒 | 本机下载约 2 秒，慢在试用者到香港服务器的线路。发布后旧 chunk 404 已由上一份 ai-log 的归档解决 | 不改代码 |
| 用户问题在标题栏和消息区各显示一次 | **属实**。标题栏直接用了第一条问题 | 标题栏改为：改过名显示新名字，否则显示「当前对话」（`chatTitle`） |
| `allow_private_base: true` 有内网请求风险 | **属实，而且比报告说的严重**。演示模式下默认允许内网地址，演示站上任何人都能一键进管理员，把模型地址指向内网服务或云元数据地址 | 默认禁止，演示模式也一样，只有显式设置 `MODEL_ALLOW_PRIVATE_BASE=true` 才放开。云元数据和链路本地地址（169.254.0.0/16、100.100.100.200、fd00:ec2::254、IPv4 映射写法）即使放开也禁止 |
| 页面缺少 CSP 和 Permissions-Policy | **报告用的是旧版本**：线上 `/`、`/login`、`/ai`、`/dashboard` 都已带上 | 不改 |
| AI 页缺一级标题、landmark；5–6 处严重对比度问题；报销表单无名称控件 | 用 axe-core 扫登录页、AI 页、报销页和新建报销弹窗：**对比度和标题、landmark 属实**；登录页演示按钮的名称和可见文字不一致；报销表单的无名称控件已在上一轮修好，本次没扫出来 | 标题行改成 `header` + `h1`（面包屑 / 标签页时 `h1` 只给读屏）；侧栏加 `role=navigation`；搜索框快捷键、侧栏分组名、用户角色、模型选择、列表计数、新增一条等 `zinc-400` 改 `zinc-500` / `zinc-600`；登录按钮去掉 `aria-label`，用可见文字加上只给读屏的「以」；`CommandDialog` 的标题移进对话框（shadcn 模板把它放在外面，关闭时也留在页面上） |

## 测试
- core：`test_private_base_blocked_by_default_even_in_demo`（回归）；元数据地址在打开内网时仍被拦截；全量 816 个通过。
- web：`chatTitle` 用例（回归）；lint / typecheck / Vitest 404 个通过；`e2e/login.spec.ts` 改为按可见文字找按钮。
- 浏览器：张晨、李薇、周敏分别打开失效会话，都提示原因、地址回到 `/ai`、1 秒内不再显示加载中。修复前后各跑一次 axe，严重问题从每页 5–7 个降到 0。全流程走查脚本重跑通过。

## AI 写错、人工修正
| 问题 | 原因 | 修正 |
|---|---|---|
| 上一轮把「演示模式默认允许内网地址」当成方便自建模型的设计 | 只想到本地开发，没想到演示站上谁都能当管理员 | 默认禁止；元数据地址永远禁止 |
| 改为默认禁止后，模型配置测试 8 个失败 | 原测试依赖演示模式跳过 DNS 解析，离线环境下解析不了 `api.moonshot.cn` | 允许内网时 DNS 失败仍放行，只拦元数据；测试文件默认按允许内网跑，回归用例单独关掉 |
| 上一轮只修了报销表单的对比度，说「表单内文字全部 ≥ 4.5:1」 | 只测了表单本身，没测外壳（侧栏、搜索、计数），那些在每页都有 | 本次用 axe 扫整页 |
| 在 Windows 上用 Python heredoc 改脚本里的中文正则，连续几次没生效 | 终端编码把「以」写坏了，正则匹配不上 | 改用编辑工具直接改 |
