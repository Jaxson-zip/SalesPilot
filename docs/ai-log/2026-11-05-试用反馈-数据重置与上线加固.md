# 试用反馈：数据被重置、静态资源与缓存、无障碍、安全头、发布可验证

- 日期：2026-11-05 · 开发者：Claude Code · 模块：seed、core（health）、infra/nginx、deploy.yml、web（客户选择、日期、表单对比度）
- 上一份：`2026-11-05-全流程走查修复.md`
- 起因：外部试用报告列了六类问题，要求逐条核实，确有其事的修掉。

## 逐条核实
| 报告的问题 | 核实结果 | 处理 |
|---|---|---|
| 王磊的 6 条报销和新建草稿全部消失，疑似部署触发了演示数据重置 | **不是部署**：流水线只做拉镜像、换容器、`alembic upgrade`、就绪检查，从不跑 seed。数据是上一轮按 AI 给的命令在线上手动执行 `seed --reset` 清掉的。但 `--reset` 不问一句就清空所有业务数据，确实危险 | `--reset` 先列出要删的数量（客户 / 商机 / 报价 / 报销 / 合同 / 回款），交互终端要输入 RESET，非交互必须加 `--yes`，否则什么都不删（`seed/guard.py`）；README、部署指南、AGENTS 写明「线上有人试用时不要跑」 |
| 密码返回「不正确」，但旧令牌仍能识别王磊 | **属实**：`seed --reset-passwords` 改了密码却没让旧登录失效（改密码、管理员重置都会 `token_version + 1`，唯独 seed 漏了）。密码变化本身来自 README 推荐的「分享前 `--reset --reset-passwords`」 | seed 重置密码时 `token_version + 1` 并清认证缓存；回归测试：登录 → 重置 → 旧 token 401 → 新密码可登录 |
| 两个脚本 25 秒只传了一部分 | 线上 JS 已 gzip、带 hash 并缓存一年，本机下载约 2 秒，慢在试用者到香港服务器的线路。**但发现两处真问题**：①发布后新 web 容器里没有旧版本的 chunk，发布前打开的页面切路由会加载失败；②`/_next/static` 里写了 `add_header`，外层安全头全部不再继承 | nginx 给 `/_next/static` 加本地缓存（`next_static`，保留 60 天，放在卷 `nginx_cache` 里），旧 chunk 发布后仍可取；安全头抽成 `snippets/headers.conf`，每个写了 `add_header` 的 location 都重新 include |
| HTML 设置了一年 CDN 缓存 | **属实**：Next.js 给预渲染页面带 `Cache-Control: s-maxage=31536000`，目前前面没有 CDN 所以没出事，一旦加 CDN，发布后用户会拿到一年前的页面 | nginx 对页面统一改为 `no-cache`（仍可 304，不多传） |
| 新建报销的客户选择控件没有读屏名称（critical）；日期控件名称不一致 | **属实**：客户选择是 `role=combobox`，combobox 不会用按钮文字当名称；日期按钮 aria-label 是「发生日期」，但看得见的文字是「2026-11-05」，名称不包含可见文字（WCAG 2.5.3） | 新增 `lib/a11y.ts` 的 `comboLabel`：名称 =「字段名：显示的文字」，客户选择和日期选择共用；Vitest 用例 |
| 表单 10 处对比度不达标，最低约 2.21:1 | **属实**（本地复测）：必填星号 `red-500` 3.81:1；报销须知里「标准 / 要求 / 票据 / 依据」`zinc-400` 2.56:1；「先选择关联客户」2.62:1 | 改为 `red-600` / `zinc-500`（≥ 4.5:1），票据、上传说明、审批时间等同类文字一起改 |
| 缺少 CSP 和 Permissions-Policy | **属实** | CSP 只允许本站资源（Next.js 水合脚本和组件内联样式需要 `'unsafe-inline'`，附件预览要 `blob:`）；Permissions-Policy 只给话筒（语音输入），摄像头、定位、支付等关闭。本地经 nginx 走查登录、工作台、报销、报价详情，控制台没有 CSP 拦截 |
| 登录令牌保存在 localStorage | **属实，本次未改**：改成 HttpOnly Cookie 要动登录、所有请求、SSE、CSRF 防护，属于单独一项改造。先用 CSP 降低被 XSS 读走的风险 | 作为后续任务单独做 |
| 没有 /health、/readyz 或版本接口 | 部分属实：core 有 `/health`，但只在容器内网，不带版本 | 新增 `/api/health`（经 nginx 对外，带 `version` = 构建时的提交 SHA）和 `/api/readyz`（未就绪返回 503）；CI 构建时传 `APP_VERSION`；发布就绪检查同时核对 `version == 本次 SHA` |
| 发布时要清缓存、保留旧静态资源；迁移和回滚不可证明 | 缓存和旧资源见上。另发现 nginx 配置是单文件挂载，`git reset` 换了文件后运行中的容器仍读旧配置，配置改动从来没有在发布时生效过 | 发布脚本：nginx 配置有变化时先用新配置 `nginx -t`，通过才重建 nginx 容器。数据库备份脚本在 `infra/backup/`，回滚演练本次没做 |

## AI 写错、人工修正
| 问题 | 原因 | 修正 |
|---|---|---|
| 上一轮让用户在线上跑 `seed --reset`，清掉了试用者的数据 | AI 只想着「让新演示数据生效」，没提醒线上可能有人在试用、也没提议先备份 | 加确认保护；文档写明线上有人试用时不要跑 |
| 新测试先写成 `/api/auth/me`，实际是 `/api/me` | 凭印象写路径 | 查 openapi 改正 |
| 第一次用脚本测对比度，把 oklch 颜色当 rgb 解析，算出全是 2.87 | 浏览器返回的是 oklch，正则取数字不对 | 改成画到 canvas 再读像素 |
