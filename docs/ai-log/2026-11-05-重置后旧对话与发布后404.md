# 重置 / 退出后 AI 仍显示旧对话；新对话偶尔失败、控制台 404

- 日期：2026-11-05 · 开发者：Claude Code · 模块：core（agent/history、seed）、web（lib/session、lib/storage）、infra/nginx、deploy.yml
- 上一份：`2026-11-05-试用反馈-数据重置与上线加固.md`
- 起因：用户反馈「数据重置后退出再登录，对话还是旧的；点新对话有时失败，还有 404」，并质疑上一轮没有真正走完全流程。

## 根因（本地复现后确认）
| 现象 | 根因 |
|---|---|
| 退出再登录，AI 工作台还是上次的对话 | 前端按用户把「上次打开的会话 id」记在 localStorage（`sp.ai.<userId>.*`），退出登录时没有清。下次登录同一个人，工作台自动打开旧会话 |
| `seed --reset` 之后旧对话仍能打开，但历史记录里没有它 | `--reset` 只清业务表，LangGraph 的 checkpoint 表（`checkpoints` / `checkpoint_writes` / `checkpoint_blobs`）不在 ORM 里，没被清。本地查到 679 个孤儿会话。读消息接口在会话登记表里找不到记录时，直接从 checkpoint 读出旧内容，所以「历史里没有、但打得开」 |
| 新对话偶尔点了没反应、控制台 404 | 线上网络日志里同一个 chunk 出现两个 hash（`9431-b549…` / `9431-8d3f…`）：发布前打开的页面切路由时去要旧版本的 JS，新 web 容器里已没有这个文件。上一轮加的 nginx 缓存只能补「以前被请求过」的文件，从没请求过的旧 chunk 仍 404，前端路由跳转失败 |

## 修改
- core：`read_thread_messages` 找不到会话登记时返回 40401「会话不存在或已被清理」，不再从 checkpoint 读孤儿数据；`seed --reset` 同时清 checkpoint 表（表不存在时跳过）。
- web：`logout()` 清掉所有 `sp.ai.` 开头的本地记录（`clearAiSessions`）。
- 走查中另外发现两处（都是「请求了不该请求的东西」，控制台有报错但不影响操作）：
  - 删除报销草稿后，抽屉关闭前它的详情查询仍挂着，`invalidateQueries(["expenses"])` 把它也重拉了一次 → 404。删除成功后先移除这张的详情缓存，其余报销查询照常刷新（`isExpenseDetailKey`）。
  - 主管切到管理员时，`switchRole` 在 `setRole` 后立刻 `invalidateQueries()`，此时 React 还没重新渲染，侧栏「待审批」查询仍处于启用状态，用管理员的登录去拉 → 403。改为 `flushSync` 先把新角色渲染出来再刷新。
- infra：新增卷 `static_archive`。发布时先把旧镜像、再把新镜像的 `/app/.next/static` 拷进去（保留 30 天）；nginx 的 `/_next/static/` 上游 404 时回退到这个归档目录。

## 测试
- core：`test_messages_unregistered_thread_404`、`test_reset_also_clears_langgraph_checkpoints`（回归）；全量 pytest 通过。
- web：`lib/__tests__/storage-prefix.test.ts`；lint / typecheck / Vitest 通过。
- nginx（本地 `--profile prod`，:8080）：放一个假的旧 chunk 进归档 → 200 且 `X-Cache-Status: ARCHIVE`；不存在的 chunk → 404；当前 chunk → HIT。
- web：`isExpenseDetailKey` 用例（回归）；lint / typecheck / Vitest 403 个通过。
- 浏览器全流程（真实 Edge 经本地 nginx :8080，与线上同一套配置；脚本 `scratch/demo-video/walk.cjs`，监听每一步的控制台错误和 ≥400 的请求）：
  张晨一键登录 → 销售 11 个页面 → AI 发消息 → 新对话 → 再发 → 历史记录 2 条 → **退出再登录，AI 为空白**（本地已无 `sp.ai.*`）→ **本地 `seed --reset` 后打开旧会话：不显示旧内容，发消息生成新会话** → 客户详情写跟进 → 报销存草稿再删除 → 切主管（13 页，AI 不显示销售的对话）→ 切管理员（12 页）→ 切刘洋只看到华东客户 → 退出后 `/api/me` 401。
  第一次跑有 7 项失败：5 项是脚本问题（新对话按钮在空白页本来就不显示；报销弹窗里有两个「保存草稿」导致后续点击被挡住），另外 2 项就是上面的 404 / 403，修复后全部通过，唯一的控制台记录是退出后脚本主动请求 `/api/me` 得到的预期 401。

## AI 写错、人工修正
| 问题 | 原因 | 修正 |
|---|---|---|
| 前几轮只验证了「登录 → 操作」，没走「退出 → 再登录」和「重置 → 再进入」 | 走查只按页面过一遍，没按用户的真实路径（换人、退出、重置、发布后继续用旧页面） | 本次走查脚本把这三条路径都写进去 |
| 上一轮说「nginx 缓存能让旧 chunk 在发布后仍可取」 | 只考虑了已缓存的文件，没考虑从未被请求过的旧 chunk | 改为发布时整体归档旧版本静态文件 |
| 归档命令第一版用 `cp -rn src/. dest/`，一个文件都没拷 | web 镜像是 BusyBox，目标目录已存在时 `-n` 行为与 GNU 不同 | 改成 `cp -r`，确认拷入 93 个文件 |
| 前几轮切换账号时只看「页面是否正确」，没看控制台 | 403 只在控制台出现，界面上看不出来 | 走查脚本把控制台错误和失败请求都算作失败 |
| 排查时一度把通知接口的大量请求当成「请求风暴」 | 没先算时间：60 秒轮询 × 约 100 分钟本来就有这么多 | 核对轮询间隔后排除 |
