# 业务模块接口契约 v1（商机 · 报价 · 合同 · 报销 · 审批 · 工作台 · 行业包配置）

> 前后端并行开发的**唯一依据**。字段名、状态值、错误码以本文为准；实现与本文不一致时先改本文。
> 通用约定沿用 `docs/开发规范.md` §8：统一响应 `{code, message, data, request_id}`；金额一律整数「分」；比例 0–1（`win_rate` 例外，为 0–100 整数，与现有表结构一致）；时间 ISO 8601。
> 列表**一律**返回 `data: {items: [...], total: number}`（包括动态、产品线、跟进记录、联系人），分页参数 `page`（从 1 开始）、`page_size`（默认 20，最大 100）。
> 数据范围参数 `view`：`mine`（本人）· `team`（本团队，仅 manager/admin）· `all`（全部，仅 admin）；销售传 `team/all` 时按 `mine` 处理。看不到的单条记录一律返回 **40401**（不返回 40301，避免泄露存在性）。

## 0. 角色与操作权限（v2，优先级高于下文各节的零散描述）

**原则**：看得到 ≠ 改得了。数据范围（view）决定能看什么；下表决定能做什么。业务数据**只有负责人本人能修改**，主管只做审批和回款，管理员只做系统配置。

| 操作 | 销售 sales | 主管 manager | 管理员 admin |
|---|---|---|---|
| 查看客户 / 商机 / 报价 / 合同 / 报销 | 本人 | 本团队 | 全公司（只读） |
| 新建客户、商机、报销；写跟进 | ✅ | ✅（记在自己名下） | ❌ |
| 修改商机、切换阶段、看板拖拽 | 本人的 | 本人的 | ❌ |
| 报价单提交 / 发送 / 客户接受 / 客户拒绝 | 本人的 | 本人的 | ❌ |
| 报销上传 / 删除票据、提交 | 本人的 | 本人的 | ❌ |
| 审批报价和报销 | ❌ | 本团队 | ❌ |
| 登记回款 | ❌ | 本团队 | ❌ |
| AI 助手：查询类工具 | ✅ | ✅ | ✅ |
| AI 助手：写操作工具（生成报价、推进商机、报销、记跟进） | ✅ | ✅（仅本人记录） | ❌ |
| AI 助手：审批工具 | ❌ | ✅ | ❌ |
| 行业包配置、产品线映射（修改） | ❌ | ❌ | ✅ |
| 产品线列表（读） | ✅ | ✅ | ✅ |

错误码：
- 看得到但无权操作 → **40301**，`data.rule = "role_forbidden"`（角色不允许，如管理员写业务数据）或 `"not_owner"`（不是负责人，如主管改销售的商机）。
- 看不到的记录 → 40401（不变）。

前端：无权操作的按钮**不显示**（不是置灰）；管理员打开业务页面时，页面顶部显示「只读」提示；导航按角色分组（销售：工作区；主管：工作区 + 团队管理；管理员：业务总览（只读）+ 系统设置）。

## 0.1 公共对象

```ts
UserBrief      { id, name }
CustomerBrief  { id, name }
OppBrief       { id, name }
ProductLineBrief { id, name, pack }          // pack 如 "llm_deploy"
```

Activity 的 `action` 代码（与 `subject_type` 组合使用，前端按「对象.动作」翻译）：

| subject_type | action |
|---|---|
| `opportunity` | `create` · `update` · `stage_changed` · `task_done` |
| `quote` | `create` · `update`（调价） · `submit` · `send` · `accept` · `reject` · `approval_approve` · `approval_reject` |
| `contract` | `create` · `payment` |
| `expense` | `create` · `submit` · `attachment_added` · `attachment_removed` · `approval_approve` · `approval_reject` |
| `customer` | `create` · `task_done` · `transfer` |

状态枚举（前端标签文字照抄）：

| 对象 | 值 → 中文 |
|---|---|
| 商机 `stage` | `lead` 线索 · `qualified` 需求确认 · `proposal` 方案报价 · `negotiation` 商务谈判 · `won` 赢单 · `lost` 输单 |
| 报价 `status` | `draft` 草稿 · `pending_approval` 待主管审批 · `approved` 已审批 · `sent` 已发送客户 · `accepted` 已成交 · `rejected` 已驳回 |
| 合同 `status` | `active` 回款中 · `paid` 已回款 |
| 报销 `type` | `entertainment` 客户招待 · `transport` 差旅交通 · `hotel` 差旅住宿 · `other` 其他 |
| 报销 `status` | `draft` 草稿 · `pending_approval` 待主管审批 · `approved` 已通过 · `rejected` 已驳回 · `paid` 已打款 |
| 审批 `status` | `pending` 待处理 · `approved` 已通过 · `rejected` 已驳回 |

|---|---|---|
| GET | `/api/opportunities?view=&stage=&customer_id=&q=&page=&page_size=` | 列表 |

```ts
OpportunityItem   { id, name, customer: CustomerBrief, stage, amount, win_rate, expected_close_date,
                    product_line: ProductLineBrief | null, owner: UserBrief, updated_at }
OpportunityDetail = OpportunityItem & { quotes: QuoteItem[], activities: Activity[] }
OpportunityCreate { customer_id, name, amount (≥0), win_rate? (0–100, 默认 10), expected_close_date?, product_line_id? }

PipelineSummary   { stages: [{ stage, count, amount }], total_amount, weighted_amount }  // weighted = Σ amount × win_rate / 100
```
规则：
- 只能给自己能看到的客户建商机（否则 40401）。
- `won` / `lost` 为终态，不能再切换 → **42201**，`data.rule = "opportunity_stage_final"`。
- 每次切换阶段写一条 Activity：`action="stage_changed"`，`content="需求确认 → 方案报价"`。

## 3. 报价单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/quotes?view=&status=&opportunity_id=&customer_id=&q=&page=&page_size=` | 列表 |
| GET | `/api/quotes/{id}` | 详情（含明细和审批记录） |
| POST | `/api/quotes/{id}/submit` | 提交：按规则自动通过或进入审批 |
| POST | `/api/quotes/{id}/send` | 发送客户 |
| POST | `/api/quotes/{id}/accept` | 客户接受 → 自动生成合同和提成 |
| POST | `/api/quotes/{id}/reject` | 客户拒绝 |

```ts
QuoteItem   { id, code, customer: CustomerBrief | null, opportunity: OppBrief | null, pack, tier, tier_name,
              total_price, total_cost, margin_rate, status, source: "agent"|"manual", owner: UserBrief, created_at }
QuoteDetail = QuoteItem & { items: QuoteLine[], approvals: ApprovalBrief[], contract_id: string | null,
                            estimated_commission: number }
QuoteLine   { sku, name, unit, qty, unit_cost, unit_price, category, subtotal_cost, subtotal_price }
ApprovalBrief { id, status, reason, approver: UserBrief | null, comment, decided_at }
```
状态流转（其余一律 **42201**，`data.rule = "quote_status_transition"`）：

| 动作 | 允许的当前状态 | 结果 |
|---|---|---|
| submit | `draft` | 毛利 ≥ 底线 → `approved`；否则 → `pending_approval` 并创建 Approval（reason 写明触发的规则） |
| send | `approved` | `sent` |
| accept | `sent` | `accepted`；创建 Contract（amount = total_price，code `C-YYYY-NNN`）+ Commission（estimated 用 `calc_commission`，confirmed = 0）；关联商机阶段改为 `won` |
| reject | `sent` | `rejected` |

阈值来自 `rules.yaml`（含行业包覆盖），不得硬编码。每次流转写 Activity。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/contracts?view=&status=&page=&page_size=` | 列表，`data` 额外带 `summary` |
| GET | `/api/contracts/{id}` | 详情 |
| POST | `/api/contracts/{id}/payments` | 登记回款（仅 manager 且合同属于本团队，否则 40301） |

```ts
ContractItem { id, code, customer: CustomerBrief | null, quote: { id, code } | null, amount, paid_amount,
```

## 5. 报销

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/expenses?view=&status=&page=&page_size=` | 列表 |
| GET | `/api/expenses/{id}` | 详情（含附件、制度校验结果） |
| POST | `/api/expenses` | 新建草稿（同时做制度校验） |
| POST | `/api/expenses/{id}/attachments` | 上传票据：`multipart/form-data`，字段 `file`、`kind` |
| DELETE | `/api/attachments/{id}` | 删除票据（仅草稿状态） |
| GET | `/api/attachments/{id}/file` | 下载 / 预览（校验数据权限） |
| POST | `/api/expenses/{id}/submit` | 提交 |
| POST | `/api/expenses/precheck` | 已有：不落库的制度校验 |

```ts
ExpenseItem   { id, code, type, amount, headcount, occurred_on, customer: CustomerBrief | null, reason,
                status, attachment_count, over_limit: boolean, owner: UserBrief, created_at }
ExpenseDetail = ExpenseItem & { participants, opportunity: OppBrief | null, attachments: AttachmentOut[],
                                policy_check: { passed, per_person, limit_per_person, over_amount, rule_ref } }
ExpenseCreate { type, amount (>0), headcount (≥1), occurred_on, participants?, customer_id?, opportunity_id?,
                reason, idempotency_key? }
```
规则：
- 附件：jpg / png / pdf，单个 ≤ 10 MB，否则 40001。
- submit 前置条件：`entertainment` 必须同时有 `invoice` 和 `receipt`；其他类型至少一张 `invoice` → 否则 **42201** `rule="expense_missing_invoice"`。
- 制度校验通过 → `approved`；超标 → `pending_approval` 并创建 Approval。
- 同一 `idempotency_key` 重复提交 → **40901**。

## 17. 报销参与人结构化

- `ExpenseCreate` 新增：`contact_ids: string[]`（客户方联系人，须属于所关联的客户）、`colleague_ids: string[]`（我方同事，须为本团队成员）、`extra_guests: number`（其他人数，≥ 0）。
- `headcount` 由后端计算 = 联系人数 + 同事数 + 申请人本人 + extra_guests（客户提交的 headcount 被忽略，向后兼容）；`participants` 文本由后端按「客户：…；我方：…」自动生成用于展示。
- `entertainment` 类型必须关联客户（`customer_id` 必填，否则 40001），且至少选择 1 名客户方联系人。
- `ExpenseDetail` 新增 `contacts: [{id,name,title}]`、`colleagues: UserBrief[]`、`extra_guests`。

### v3 实现说明（后端落地后补充）
- 任务「今天 / 逾期」按北京时间自然日：到期日早于今天且未完成才算逾期；`due=week` 为今天起 7 天内；`PATCH {done:false}` 可重新打开任务。
- `/api/users`：管理员总是返回全部用户，其他角色总是返回本团队（`scope` 参数不改变结果）。
- 转移目标不在本团队 → 40301 `rule=not_team`；目标用户不存在 → 40401；参与人校验失败 → 40001（`data.errors[].loc` 指向字段）。
- `PATCH /api/quotes/{id}/items` 提交**完整明细**（未列出的行会被删除）；非草稿 → 42201 `rule=quote_not_editable`；是否需要审批仍在提交时判断。`QuoteDetail` 另有 `list_price`（折前合计）。
- 通知 `link`：报价 `/quotes/{id}`、报销 `/expenses?id={id}`、商机 `/pipeline?opportunity={id}`、客户 `/customers/{id}`。

## 26. 客户批量导入

> 2026-10-29 新增。销售、主管可用；管理员对业务数据只读（403）。

- 查重：与新建客户相同的核心名规则，全公司范围；已存在 → `duplicate`；文件内重复只保留第一行；名称相似但不相同 → `ok` + `warnings`。
- `ImportResult`：`total`、`ok`（预览为可导入数，导入为新建数）、`skipped`、`created`、`columns`、`ignored_columns`、`rows[]`（`line`、`name`、`owner_name`、`status` ok / duplicate / error、`message`、`warnings`）。
- 每个新客户写一条动态 `import`；填了联系人时同时建联系人。
