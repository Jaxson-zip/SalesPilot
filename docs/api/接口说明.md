# 接口说明

SalesPilot 对外只有一个服务入口：core 的 `/api/*`。前端、脚本、测试都调它；模型网关在内网，不直接对外。

| 文档 | 用途 |
|---|---|
| 本文 | 约定、错误码、主要接口的请求 / 响应示例（**示例都是从本地运行的系统里实际抓到的**，只删减了过长的列表） |
| [openapi.yaml](openapi.yaml) | 全部 130 个接口的字段定义，由代码导出，有测试保证与代码一致 |
| Swagger 页面 | 本地启动后打开 http://127.0.0.1:8000/docs（core 直连端口），可以直接在页面上调用 |
| [业务模块接口契约.md](业务模块接口契约.md) | 前后端并行开发时的逐版契约（状态值、权限矩阵、每一版的变更） |

## 1. 约定

**地址**：本地 `http://127.0.0.1:3000/api/...`（经前端代理）、`http://127.0.0.1:8080/api/...`（经 nginx，与线上一致）或 `http://127.0.0.1:8000/api/...`（直连 core）；线上 `https://crm.jaxson.bond/api/...`。

**登录与鉴权**：二选一。

| 方式 | 用法 | 适合 |
|---|---|---|
| HttpOnly Cookie | 登录接口会设置 `sp_session` Cookie，之后浏览器自动带上。**写请求必须带 `X-Requested-With` 请求头**（CSRF 防护），否则 40301 | 网页 |
| Bearer Token | 登录响应里的 `data.token`，放到 `Authorization: Bearer <token>` | 脚本、接口测试 |

改密码、管理员重置密码、账号停用都会让旧 token 立即失效（`token_version` 校验）。

**统一响应**：所有接口（流式接口除外）都返回同一个外壳。

```json
{ "code": 0, "message": "ok", "data": { }, "request_id": "d972a526f5effe15862c2f8007184e7e" }
```

- `code` 为 0 表示成功；非 0 时 HTTP 状态码与之对应（见下表），`message` 是可以直接显示给用户的中文说明；
- `request_id` 同时在响应头 `X-Request-ID` 里，请求时也可以自己带上，会在 web → core → gateway 之间透传，排查日志用；
- **金额一律是整数「分」**（`46000000` = 46 万元），时间是 ISO 8601（UTC），由前端格式化；
- 列表接口统一 `page` / `page_size`（最大 100），返回 `{ "items": [...], "total": n }`。

## 2. 错误码

| code | HTTP | 含义 | 常见场景 |
|---|---|---|---|
| 0 | 200 | 成功 | |
| 40001 | 400 | 参数校验失败，`data.errors[]` 逐项列出 | 必填项为空、格式不对、上传的文件损坏 |
| 40002 | 400 | 模型能力不匹配 | 选的模型不支持工具调用 / 图片 |
| 40101 | 401 | 未登录或登录已失效 | 没带 Cookie / token，或已改过密码 |
| 40301 | 403 | 无权限，`data.rule` 说明原因 | `role_forbidden`（角色不允许）、`not_owner`（不是负责人）、`csrf`（缺请求头） |
| 40401 | 404 | 不存在，**或无权查看**（不区分，避免泄露其他团队的数据） | 访问其他团队的客户、已删除的会话 |
| 40901 | 409 | 重复 | 同名客户、重复提交 |
| 42201 | 422 | 业务规则不满足，`data.rule` 说明是哪条规则 | 阶段不能跳、报价已发送不能改 |
| 42901 | 429 | 模型限流 / 当日 AI 额度用完 | |
| 50001 | 500 | 内部错误（带 `request_id`，按它查日志） | |
| 50201 | 502 | 模型网关上游错误 | 模型厂商故障且备用模型也失败 |
| 50301 | 503 | 服务暂不可用 | 数据库连接不上 |
| 50401 | 504 | 模型调用超时 | |

错误示例（都是实际返回）：

```http
GET /api/me                      （未登录）
→ 401 {"code":40101,"message":"未登录或 token 失效","data":null,"request_id":"01b3…"}

POST /api/customers  {"name":"","level":"Z"}
→ 400 {"code":40001,"message":"客户名称不能为空",
       "data":{"errors":[{"loc":["body","name"],"msg":"客户名称不能为空"},
                         {"loc":["body","level"],"msg":"Input should be 'A', 'B' or 'C'"}]},
       "request_id":"e3cc…"}

GET /api/approvals               （销售访问审批）
→ 403 {"code":40301,"message":"仅销售主管可以处理审批","data":{"rule":"role_forbidden"},"request_id":"fc22…"}

POST /api/customers              （Cookie 登录但没带 X-Requested-With）
→ 403 {"code":40301,"message":"请求缺少 X-Requested-With 请求头（CSRF 防护）","data":{"rule":"csrf"},"request_id":"5fc9…"}

GET /api/customers/00000000-0000-0000-0000-000000000000
→ 404 {"code":40401,"message":"资源不存在","data":null,"request_id":"e91e…"}
```

## 3. 主要接口

全部接口见 [openapi.yaml](openapi.yaml)，按模块：认证与账号（`/api/auth/*`、`/api/me`、`/api/admin/*`）、客户与联系人（`/api/customers/*`）、商机（`/api/opportunities/*`、`/api/pipeline/*`）、报价（`/api/quotes/*`）、合同 / 回款 / 开票（`/api/contracts/*`）、报销（`/api/expenses/*`）、审批（`/api/approvals/*`）、任务与通知、行业包与规则（`/api/packs/*`、`/api/settings/*`）、AI（`/api/agent/*`）、健康检查（`/api/health`、`/api/readyz`）。

### 3.1 健康检查 `GET /api/health`（无需登录）

```json
{ "code": 0, "message": "ok",
  "data": { "status": "ok", "db": true, "checkpointer": "PostgresSaver", "persistent": true,
            "version": "5e36af8…" },
  "request_id": "d972…" }
```

`version` 是构建时的提交号，发布流水线用它确认新版本已经上线。`GET /api/readyz` 在数据库不可用时返回 503。

### 3.2 演示账户登录 `POST /api/auth/mock-login`

仅演示模式（`DEMO_LOGIN=true`）可用；正式模式用 `POST /api/auth/login`（用户名 + 密码）。

```http
POST /api/auth/mock-login
Content-Type: application/json
X-Requested-With: fetch

{ "role": "sales" }                 // sales / manager / admin；可加 "username" 指定同角色的其他演示账号
```

```json
{ "code": 0, "message": "ok",
  "data": { "token": "eyJhbGciOiJIUzI1NiIs…",
            "user": { "id": "803849e9-…", "name": "张晨", "role": "sales", "team_id": "0a87843a-…" } },
  "request_id": "…" }
```

同时响应头 `Set-Cookie: sp_session=…; HttpOnly; SameSite=Lax`（经 HTTPS 时带 `Secure`）。线上如果设置了访问口令，请求体还要带 `access_code`。

### 3.3 当前用户 `GET /api/me`

```json
{ "code": 0, "message": "ok",
  "data": { "id": "803849e9-…", "name": "张晨", "role": "sales", "team_id": "0a87843a-…",
            "team_name": "华南销售组", "username": "zhangchen",
            "must_change_password": false, "solo_mode": false },
  "request_id": "fe78…" }
```

### 3.4 客户列表 / 详情 / 新建

`GET /api/customers?page=1&page_size=20&q=华南&view=mine` —— 数据权限在服务端过滤：销售只看到自己的，主管看到本团队的，管理员看到全部。

`GET /api/customers/{id}`：

```json
{ "code": 0, "message": "ok",
  "data": { "id": "1b629913-71eb-52b7-856e-4855cbe293a0", "name": "华南智能制造有限公司",
            "industry": "制造业", "level": "A", "size": "800 人", "address": "东莞市松山湖",
            "website": "hnzz.com", "annual_budget": 60000000, "opportunity_amount": 46000000,
            "owner": { "id": "803849e9-…", "name": "张晨" },
            "tags": [], "last_followup_at": "2026-11-05T08:50:10Z", "created_at": "2026-11-05T08:50:01Z" },
  "request_id": "7d50…" }
```

`POST /api/customers`（新建）：

```json
{ "name": "深圳示例科技有限公司", "industry": "制造业", "level": "B", "annual_budget": 50000000 }
```

成功返回新客户（同详情）；名称为空 / 等级不对 → 40001（见上）；与已有客户重名 → 40901。

### 3.5 商机与阶段

`GET /api/opportunities?page_size=1`：

```json
{ "code": 0, "message": "ok",
  "data": { "items": [ { "id": "1201b86b-…", "name": "AI 客服",
                         "customer": { "id": "c46487d4-…", "name": "前海云帆科技" },
                         "stage": "lead", "amount": 15000000, "win_rate": 10,
                         "expected_close_date": "2026-11-30",
                         "product_line": { "id": "7b358c2d-…", "name": "大模型私有化部署", "pack": "llm_deploy" },
                         "owner": { "id": "803849e9-…", "name": "张晨" } } ],
            "total": 6 },
  "request_id": "…" }
```

`PATCH /api/opportunities/{id}/stage`，请求体 `{"stage": "proposal"}`。阶段：`lead → qualified → proposal → negotiation → won / lost`。赢单需要有报价单（可同时传 `quote_id` 按这张报价成交，自动生成合同、回款计划和提成），否则 42201；输单必须填 `lost_reason`，否则 40001。

`GET /api/pipeline/summary` 按阶段汇总数量与金额（看板顶部的漏斗）。

### 3.6 报销预检 `POST /api/expenses/precheck`

填写报销时实时调用：标准由 `rules.yaml` 配置、由规则代码计算，不经过大模型。

```json
{ "category": "meal", "amount": 186000, "attendees": 4,
  "occurred_at": "2026-11-04T19:00:00+08:00", "reason": "客户方案沟通晚餐" }
```

```json
{ "code": 0, "message": "ok",
  "data": { "per_person": 186000, "limit_per_person": 15000, "over_amount": 171000,
            "need_approval": true,
            "reason": "人均 ¥1860 超出标准 ¥150/人，超出 ¥1710",
            "unit": "person", "rule_ref": "《费用报销管理制度》4.2 招待标准" },
  "request_id": "2ea2…" }
```

之后 `POST /api/expenses` 存草稿、`POST /api/expenses/{id}/attachments` 上传票据（只收 jpg / png / pdf，按文件内容识别类型）、`POST /api/expenses/{id}/submit` 提交；超标的自动进入主管审批（`/api/approvals`）。

### 3.7 工作台 `GET /api/dashboard`

```json
{ "code": 0, "message": "ok",
  "data": { "won_amount_month": 109600000, "target_month": 80000000,
            "open_opportunities": 4, "open_amount": 122000000,
            "estimated_commission_month": 5428000, "confirmed_commission_month": 3160000,
            "pending_approvals": 2, "pending_quotes": 1, "pending_expenses": 1,
            "tasks_today": 1, "tasks_overdue": 1,
            "funnel": [ { "stage": "lead", "count": 1, "amount": 15000000 } ] },
  "request_id": "…" }
```

提成（`*_commission_*`）由规则代码按 `rules.yaml` 的比例和回款进度计算。

### 3.8 AI 对话 `POST /api/agent/chat`（SSE 流式）

```json
{ "thread_id": "t_doc_sample_1", "message": "华南智能制造的商机现在到哪一步了？一句话回答",
  "mode": "work" }
```

`thread_id` 由前端生成（同一会话保持不变）；`mode` 为 `work`（做方案，可调用写工具）或 `learn`（学习问答，只读）。响应是 `text/event-stream`，下面是一次实际调用的事件（`message.delta` 省略了中间部分）：

```text
event: node.start
data: {"node": "router"}

event: node.start
data: {"node": "tool_agent"}

event: tool.start
data: {"call_id": "call_31df2645f127", "name": "search_customer", "args": {"keyword": "华南智能制造"}}

event: tool.end
data: {"call_id": "call_31df2645f127", "summary": "华南智能制造有限公司", "result": [ … ]}

event: tool.start
data: {"call_id": "call_6d8b3f08d989", "name": "get_customer_context", "args": {"customer_id": "1b629913-…"}}

event: tool.end
data: {"call_id": "call_6d8b3f08d989", "summary": "1 个商机，1 位联系人", "result": { … }}

event: message.delta
data: {"text": "华南"}
…（逐段输出）…
data: {"text": "华南智能制造的「质检助手」商机目前处于**方案报价**阶段，金额 46 万元，下一步是电话跟进刘经理确认报价。"}

event: node.start
data: {"node": "respond"}

event: done
data: {"thread_id": "t_doc_sample_1"}
```

| 事件 | 含义 | 前端动作 |
|---|---|---|
| `node.start` | 进入状态图的某个节点 | 可选：显示当前步骤 |
| `tool.start` / `tool.end` / `tool.error` | 调用业务工具（工具是 service 的薄包装，权限与网页一致） | 时间线显示每一步 |
| `message.delta` | 回答的文字片段 | 追加显示 |
| `interrupt` | **写操作待确认**：`{"action": "add_followup", "preview": {…}}` | 显示确认卡；用户点确认后调 `POST /api/agent/resume`，请求体 `{"thread_id": "…", "decision": "approve"}`（或 `reject`） |
| `done` / `error` | 本轮结束 / 出错（`{"code": 50201, "message": "…"}`） | |

AI 的写操作（记跟进、推进商机、生成报价、提交报销）**一定先发 `interrupt`**，用户确认后才执行。生成过程在后台运行：断开连接不会中断，`GET /api/agent/threads/{id}/stream` 可以重新接上；`GET /api/agent/threads/{id}/messages` 读取历史（不存在或不是本人的会话 → 40401）。

## 4. 用 curl 联调

Windows 下用 `127.0.0.1`（`localhost` 可能解析到 IPv6 而卡住），中文请求体写到 UTF-8 文件里再用 `--data-binary @文件` 发送。

```bash
# 1) 服务是否就绪
curl -s http://127.0.0.1:8080/api/health

# 2) 用演示账户登录，取 token（需要 jq；没有 jq 就从输出里复制 data.token）
TOKEN=$(curl -s -X POST http://127.0.0.1:8080/api/auth/mock-login \
  -H 'Content-Type: application/json' -H 'X-Requested-With: fetch' \
  -d '{"role":"sales"}' | jq -r .data.token)

# 3) 带 token 调业务接口
curl -s http://127.0.0.1:8080/api/customers?page_size=2 -H "Authorization: Bearer $TOKEN"

# 4) 报销预检（中文写到文件里）
echo '{"category":"meal","amount":186000,"attendees":4,"occurred_at":"2026-11-04T19:00:00+08:00","reason":"客户晚餐"}' > body.json
curl -s -X POST http://127.0.0.1:8080/api/expenses/precheck \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' --data-binary @body.json

# 5) AI 对话（-N 关闭缓冲，逐条看到 SSE 事件；需要配置了模型 Key）
curl -N -X POST http://127.0.0.1:8080/api/agent/chat \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"thread_id":"t_curl_1","message":"hello"}'
```

完整的自动化联调在 `tests/e2e/`（接口端到端）和 `apps/web/e2e/`（浏览器端到端），说明与结果见 [测试与联调报告](../测试与联调报告.md)。
