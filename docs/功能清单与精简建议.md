# 功能清单与精简建议

2026-10-30 整理。目的：先想清楚这个系统解决什么问题，再决定哪些功能留、哪些收、哪些砍。

## 这个系统解决什么问题

接单的人（个人或小公司）收到客户需求后，要尽快给出**靠谱的方案和报价**，并跟到签约回款。

难点有两个：
1. 方案要专业，不能漏模块；
2. 报价要守规矩，不能报亏。

所以 AI 只负责理解需求、拆模块、写方案，价格和毛利由规则计算，超出权限的折扣要人批。

主线只有一条：

```
客户 → 商机 → AI 出方案和报价 → 报价单（打印 / 发给客户）→ 合同 → 回款
```

不在这条线上的功能，要么服务于它，要么就是负担。

## 用户是谁

| 阶段 | 用户 | 需要什么 |
|---|---|---|
| 现在 | 我自己（个人或小公司接单） | 主线 + 产品价格 + 模型接入，**不需要**角色、审批、提成、日报 |
| 期末答辩 | 老师 | 看到完整业务和三种角色，所以演示数据要保留团队功能 |
| 以后卖给企业 | 有销售团队的公司 | 再打开团队功能：主管审批、提成、目标、日报 |

结论：**团队相关的功能做成可以整体关掉的「团队模式」**。自己用时关掉，答辩和卖给企业时打开。不用删代码，也不用维护两个版本。

## 现有功能逐项判断

侧边栏现在有 19 个入口（管理员「系统设置」占 9 个）。

| 功能 | 在主线哪一步 | 谁用 | 建议 |
|---|---|---|---|
| AI 方案工作台（做方案） | 出方案、报价 | 销售 | **保留，核心** |
| AI 学习问答 | 无（新人熟悉业务） | 新员工 | 归入团队模式；个人用不需要 |
| 客户 | 起点 | 销售 | **保留** |
| 商机 | 跟进 | 销售 | **保留** |
| 报价单 | 报价 | 销售 | **保留**。可以让 AI 出，也可以自己新建；单价、数量、额外费用都能改 |
| 合同与提成 | 签约、回款 | 销售 / 主管 | 保留合同和回款；**提成**归入团队模式 |
| 工作台（首页） | 汇总 | 所有人 | 保留，但只放「待跟进商机、待发报价、待回款」三件事 |
| 业务规则 | 定价规则 | 管理员 | **和「行业包配置」合并成「产品与定价」** |
| 行业包配置 | 产品目录、知识库 | 管理员 | 同上 |
| 模型接入 | 让 AI 能用 | 管理员 | 保留（本次已简化） |
| 审批 | 折扣超权限 | 主管 | 团队模式；个人用时自己就是审批人，不需要这一步 |
| 报销 | 跟单成本 | 销售 / 主管 | **保留，照常走审批**。驳回必须写原因，员工改完在同一张单上重新提交（票据不用重传，也避免同一张发票报两次）。请客户吃饭、出差是公司该报的钱，报销已能关联客户和商机；以后在商机上显示「已花费用」，算这单实际赚多少 |
| 日报 | 无 | 销售 / 主管 | 团队模式 |
| 业绩目标 | 无 | 主管 | 团队模式 |
| 竞品战卡 | 辅助出方案 | 销售 | 不单独占入口，作为知识库内容给 AI 用 |
| 成员与团队 | 管人 | 管理员 | 团队模式 |
| 消息推送（企业微信） | 提醒 | 管理员 | 收进「系统」页 |
| 定时任务 | 提醒 | 管理员 | 收进「系统」页 |
| AI 用量 | 控制成本 | 管理员 | 收进「系统」页 |
| 操作日志 | 追溯 | 管理员 | 收进「系统」页 |
| 使用说明 | — | 所有人 | 保留，内容压短 |

按这个改完，个人使用时的侧边栏：

```
AI 方案工作台
工作台 / 客户 / 商机 / 报价单 / 合同 / 报销
设置：产品与定价 / 模型接入 / 系统
```

从 19 个入口减到 10 个。打开团队模式后再出现审批、提成、目标、日报、成员与团队。

## 关于分组和行业包

- 现在只有一个「华南销售组」，产品线是否要分开还没定。**在没有真实需求前，不再加分组相关功能。**
- 行业包本来就是**跟着商机的产品线走的**：建商机时选产品线，AI 就用对应行业包。团队默认行业包只在不从商机进入时兜底。
- 所以真正要决定的是「我卖几种东西」，而不是「我有几个组」。卖一种东西就只建一条产品线，团队设置可以完全不管。

## 「AI 味太重」的具体问题和改法

| 问题 | 例子 | 改法 |
|---|---|---|
| 说明写太多 | 几乎每个输入框都有一行灰色提示，页面顶部常有要点列表 | 只在会填错的地方写提示；默认用户知道自己在干什么 |
| 句子太长 | 一句话里两三个分号、括号套括号 | 一句只说一件事，能删的形容词都删 |
| 把实现细节给用户看 | 别名、协议、适配名、契约测试、向量化 | 用用户的词：「知识库」而不是「向量模型」 |
| 每页一个套路 | 标题、说明、卡片、提示、按钮，没有主次 | 每页先回答「这页最重要的一件事」，放在最上面 |
| 演示数据太整齐 | 客户名、金额过于规整 | 用真实接单的数据替换（脱敏后） |

模型接入页按这个思路改完了，可以作为其他页面的参考：
- 顶部一行状态；
- 中间只有填 Key；
- 其余全部收进「高级设置」。

## 建议的执行顺序

1. **团队模式开关**：一个系统设置项，关掉后隐藏团队相关入口和流程（审批改为自动通过、不算提成）。改动面最大，但收益也最大。
2. **合并设置页**：业务规则 + 行业包 → 产品与定价；推送、定时任务、用量、日志 → 系统。
3. **文案统一压一遍**：按上表的标准，逐页删提示、缩短句子。
4. **报销接到商机上**：商机页显示这单已花的费用，和报价毛利放在一起看。
5. 用自己真实接的一单走一遍主线，哪里卡就改哪里，不再凭想象加功能。

每一步做完都可以单独提交和演示，不影响答辩。

## 审查结果（2026-10-30）

### 主线链路

| 环节 | 结果 | 依据 |
|---|---|---|
| 客户 → 商机 | 通 | 商机必须挂客户，选产品线后自动匹配行业包 |
| 商机 → AI 出方案 → 报价单 | 通 | AI 出方案时直接生成报价单并关联商机 |
| 报价 → 审批 | 通 | 毛利低于底线、折扣超权限自动转主管审批，驳回回到草稿 |
| 报价 → 发送 → 客户接受 → 合同 | 通 | 接受后自动生成合同、回款计划、预估提成，商机变为赢单 |
| 合同 → 开票 → 回款 → 提成 | 通 | 回款按比例确认提成，回款完成后合同变为「已回款」 |
| 报销 → 商机 | **原来断开，已补上** | 报销能关联商机，但商机里看不到。现在商机详情显示「跟单费用」（已批 / 审批中） |

以上环节都有后端接口测试覆盖（`test_quotes_contracts_api`、`test_sales_flow_api`、`test_expenses_approvals_api`）。

商机详情新增「这单赚多少」：报价毛利 − 预估提成 − 跟单费用（已批 + 审批中）。成交前按最新一张没被拒的报价估算，成交后按客户接受的报价算。

### 页面样式

已修：
- 管理员「系统设置」从 9 个入口合并成 5 个：成员与团队、模型接入、产品与定价、竞品战卡、系统。合并的页面在顶部用标签页切换。
- 行业包页面：两段长说明压成一句话加一条提醒，去掉了给开发看的「如何新增行业包」。
- AI 工作台首页：示例卡片从 8 个减到 4 个，去掉底部两行提示，副标题缩短。
- 所有主要页面在 1280 和 390 宽度下截图检查，没有横向溢出。

- 本机数据库里有大量「E2E…」开头的测试客户和商机（之前跑浏览器测试留下的），看板和动态里很显眼。运行 `pnpm e2e:reset` 可以清掉。
