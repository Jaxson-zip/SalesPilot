### 1.2 Agent 全链路（function calling）

用「剧本模型」代替真实大模型（按顺序返回预设的工具调用），工具调用真实的 service 和测试库：

| 用例 | 验证点 |
|---|---|
| 推进商机 | `search_customer` → `get_customer_context` → `update_opportunity_stage` 停在确认卡片，库里阶段不变；确认后阶段变为商务谈判，工具结果以 JSON 回传模型，模型给出最终回复 |
| 取消写操作 | 选择取消后不写库，模型收到「用户取消了该操作」 |
| 对话报销 | 确认卡片显示客户名、金额、参与人；幂等键由系统生成（`agent:<会话>:<调用 id>`），不采用模型编造的值 |
| 角色限制 | 管理员根本拿不到写工具；即使模型调用也被拒绝 |
| 模型不可用 | 第一次调用就失败时，路由和工具选择回落到关键词规则，事件流照常结束 |
| 制度问答出处 | 检索命中时推送 `sources`，并保存进会话历史 |

                                              └──▶ db :5432（业务数据 / 向量 / 会话状态）

## 3. 问题排查过程（节选）

完整记录见 [docs/ai-log/](ai-log/)。

| 问题 | 现象 | 排查 | 原因与修正 |
|---|---|---|---|
| 网关容器启动即退出 | `docker compose ps` 显示 gateway 反复重启 | 看容器日志，配置项的值里出现了注释文字 | `.env` 行内注释被当成值；去掉行内注释、配置忽略空值，补回归测试 |
| 改了代码页面没变化 | 构建「成功」但行为还是旧的 | 仔细看构建输出，依赖下载失败，旧镜像仍在运行 | 每次以 `Image … Built` 为准，失败重试 |
| curl 调接口卡住 | Windows 下请求 `localhost` 无响应 | `localhost` 解析到 IPv6 | 一律使用 `127.0.0.1`，写入 AGENTS.md |
| 偶发「上传了票据却显示没有」 | 浏览器测试时过时不过 | 对照 core 日志：上传 200，紧接着的详情查询里没有票据 | FastAPI 带 yield 的依赖在响应发出后才提交事务；改为响应前提交，补测试 |
| 侧栏打开时「撤销」点不了 | 浏览器测试点击超时 | 在页面里用 `elementFromPoint` 检查，命中的是侧栏 | 模态侧栏让 toast 继承了 `pointer-events:none`；恢复 toast 可点击，点 toast 不关闭侧栏 |
| request_id 端到端测试失败 | 网关日志里找不到 ID | 加了模型可用性缓存后，对话不一定调网关；网关也只在 chat 调用时记 ID | 网关对每个请求记 request_id；测试改走每次都访问网关的接口 |
| 网关日志出现 `/v1/models 401` | 怀疑 core 密钥配错 | 对比两个容器里密钥的哈希，一致 | 来自测试里故意用错误 Key 的用例，属于正常 |
| Nginx 覆盖了请求 ID | 响应头里的 ID 与客户端传入的不同 | 读配置：`X-Request-ID $request_id` 总是用 Nginx 自己生成的 | 改为客户端带了就透传，没带才生成；去掉重复的响应头 |
| PDF 入库内容错乱 | 标题和正文粘连、页眉页码混进正文、全角标点变半角 | 把提取结果写到文件逐页对照 | 详见《知识库构建说明》§2，四个问题都有回归测试 |
| 「参考来源」从来没显示过 | 盘点「回答必带出处」时发现 | 前端有 sources 组件，core 从不推送 | 制度检索命中时推送 sources 并保存到会话历史，补测试 |
| 配了 Key 却看不到模型 | 前端仍显示规则模式 | 容器启动时间早于 `.env` 修改时间，容器里 Key 为空 | 改 `.env` 后需重建容器：`docker compose up -d --force-recreate gateway core` |
| 真实模型的工具调用全部 502 | 纯文本对话正常，带 tools 的请求都失败，AI 退回规则模式 | 直接调网关拿到上游错误 `No module named 'mcp'`；追到 litellm 1.106 遇到 tools 会导入 MCP 模块 | 依赖改为 `litellm[mcp]`；补一个走真实 litellm 的 tools 用例（卸掉 mcp 时该用例失败）。之前没 Key，契约测试一直跳过，所以没暴露 |
| AI 回复里的表格挤成一行 | 「\| 商机 \| 阶段 \| …」原样显示 | react-markdown 默认不支持表格 | 加 remark-gfm，表格外层可横向滚动；补渲染测试 |
| 制度问答把「502 网关错误」说给销售 | 没配 Embedding 时知识库不可用 | `search_policy` 把异常原样交给模型 | 知识库不可用时返回 `rules.yaml` 的标准并标明无出处；提示词禁止提技术细节 |
| 契约测试「上下文超长」失败 | DeepSeek 接受了 2 倍 max_context 的输入 | 看用量：25.6 万 token 仍返回 200 | 上游不一定报超长；改为上游接受时跳过并写明实测 token 数，`max_context` 从 64000 改为 128000 |
| 模型用文字问「确认吗」，再弹卡片 | 推进商机时没有调用工具，只回了一句「确认要推进吗」 | 提示词只说写操作会弹卡片，没说要直接调用 | 提示词改为信息齐全时直接调用工具，由卡片确认，避免确认两次 |
| 确认后的回复跑到卡片上面 | 截图里「已创建提醒任务」在确认卡片之前 | 确认前后的文字拼在同一个 `text` 里，卡片固定渲染在正文后 | 确认后的续写单独存为 `afterText`，显示在卡片下面；补 reducer 测试 |
| AI 审批后侧栏待审批数不变 | 审批已通过，侧栏仍显示「审批 2」 | 对话结束只刷新会话列表 | 本轮确认过写操作时刷新全部业务数据 |
| 回复里出现「approval_id」 | 审批回复说「我需要先拿到 approval_id」 | 模型在叙述内部步骤 | 提示词禁止字段名和内部步骤描述 |
| 通义超长请求 504 | 契约测试「上下文超长」等了 30 秒才失败 | 通义收到 2 倍窗口的输入不报错也不返回 | 网关兼容层按 max_context 本地估算拦截（留 25% 余量），统一返回 `context_length_exceeded` |
| 评测命中率 92% | 唯一判错的题，检索第一条其实就是正确内容 | 评测集把期望章节写成「4.3」，原文 4.3 是段落不是标题 | 修正标注；单元测试改为同时检查期望章节存在 |
| Embedding 入库会超批次上限 | 切换通义前核对接口限制 | 入库每批 16 条，通义单次最多 10 条 | 改为 10 条并加测试；Embedding 分组只放一个模型 |
