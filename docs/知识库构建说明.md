# 知识库构建说明

> 对应课程要求「知识库构建说明（资料来源、切块策略、检索参数、效果观察）」和架构设计 §5。
> 代码：`services/core/app/rag/`（`loaders.py` 加载、`chunking.py` 切块、`ingest.py` 入库、`retriever.py` 检索、`evaluate.py` 评测、`autoload.py` 启动自动入库）。

## 1. 资料来源

知识按「分区（scope）」存放：检索时只查「公司制度 + 当前商机对应的行业包」，不同行业的知识互不干扰。

| 文档 | 格式 | 分区 | 内容 | 块数 | 块长度（字） |
|---|---|---|---|---|---|
| 费用报销管理制度 | Markdown | company | 差旅交通 / 住宿标准、客户招待标准、票据要求 | 8 | 21–63 |
| 销售提成制度 | Markdown | company | 提成比例、低毛利减半、按回款确认 | 3 | 24–42 |
| 合同审批与回款流程 | **PDF**（2 页，带页眉页码） | company | 报价 / 合同分级审批、付款比例、逾期回款、提成扣回 | 9 | 21–169 |
| 显存估算参考表 | Markdown | pack:llm_deploy | 显存公式、精度选择、卡数规则 | 3 | 64–178 |
| vLLM 部署规范 | Markdown | pack:llm_deploy | 环境、部署参数、监控运维 | 3 | 75–122 |
| GPU 与整机参数表 | **Excel**（3 张工作表） | pack:llm_deploy | GPU 卡参数、整机配置与可部署模型、选型问答 | 3（表格） | 181–499 |
| 办公设备选型指南 | Markdown | pack:it_office | 岗位配置、保修政策 | 2 | 22–90 |

- 公司制度放在 `services/core/seed/knowledge/company/`，由管理员维护；行业知识放在各行业包的 `knowledge/` 目录，随行业包发布。
- 示例 PDF 和 Excel 的源文件和生成脚本在 `seed/knowledge/sources/`（`build_pdf.mjs` 把 HTML 打印成 PDF，`build_xlsx.py` 生成 Excel）。
- **价格不进知识库**：参数表里没有价格，价格只在行业包的 `catalog.json`；报销标准、毛利底线等数字以 `rules.yaml` 为准，知识库只提供制度依据和出处。

## 2. 加载与清洗

| 格式 | 处理方式 |
|---|---|
| Markdown | 按 `#` / `##` / `###` 标题拆成小节，块上记录标题路径（如「费用报销管理制度 > 4 客户招待 > 4.2 招待标准」） |
| PDF | 按页提取（pypdf），块上记录页码；去掉页眉页脚和页码；识别「第 X 章」「2.1 xxx」这类标题，转成标题路径；只把被排版折断的长行合并回段落 |
| Excel | 每张工作表转成一张 Markdown 表格（第一行作表头），工作表名作为章节；去掉全空的行和列 |

开发中发现并修正的 PDF 问题（都有回归测试，见 `tests/unit/test_rag_loaders.py`）：

1. **标题和正文粘在一起**（「第一章 总则1.1 本流程适用于…」）：最初按「行尾没有句末标点就合并」处理折行，标题和表格行都被并进了正文。改为识别标题，并且只合并长度接近整行宽度的行。
2. **页眉页脚没去掉**：文档只有 2 页，而最初要求至少 3 页才判断重复行；另外 pypdf 把「示」「页」提取成了康熙部首字符（`⽰` `⻚`），和正文对不上。改为 2 页起判断，并把部首字符规范化。
3. **全角标点被改成半角**：第一次规范化对整行做 NFKC，「，：（」都变成了半角。改为只处理部首和兼容汉字区的字符。
4. **章节路径错误**（「第一章 总则 > 第二章 审批权限」）：标题路径按级别下标截断，PDF 没有一级标题时同级标题会互相嵌套。改为标题栈。

## 3. 切块策略

| 参数 | 取值 | 理由 |
|---|---|---|
| 块长度 / 重叠 | 800 / 120 字符 | 与课程推荐值一致；制度条款一般 300–800 字，能整条放进一块 |
| 分隔符优先级 | `\n## ` → `\n### ` → 空行 → `。` → `；` → `，` | 先按标题、段落切，尽量不把一条制度拆开 |
| 表格 | 整张表作为一块；超过 800 字时按行切开，**每块都重复表头** | 防止参数表被切碎后只剩数字、看不出是哪一列 |
| 去重 | 按「分区 + 文档 + 章节 + 内容」计算 SHA-256，已入库的块跳过 | 「建库一次，多次复用」：重复执行入库不会重复调用 Embedding |
| 向量化文本 | 「文档名 > 章节」+ 换行 + 正文 | 制度条款很短，章节标题本身是重要语义；只改向量化输入，展示的内容不变 |

观察：现有资料的每个小节都比较短，基本「一节一块」，没有触发 800 字切分；参数表整表入库（最长 499 字）。资料变多后，长段落才会按分隔符切分。

## 4. 检索参数与回答边界

| 参数 | 取值 |
|---|---|
| 向量库 | PostgreSQL + pgvector（与业务数据同库），HNSW 索引，余弦距离 |
| Embedding | 经模型网关调用（分组 `embed`，默认混元 Embedding，维度写在配置 `EMBEDDING_DIMS`） |
| 检索范围 | 公司制度 + 当前商机对应的行业包 |
| top_k / 阈值 | 取前 8 条，相似度低于 0.5 的丢弃 |
| 重排 | 未启用（计划：有通义 Key 时经网关接入 gte-rerank 取前 4） |

回答边界（防编造）：

- `search_policy` 没有任何片段超过阈值时返回 `found=false`，系统提示词要求 AI 回答「制度中未找到相关规定，建议咨询财务」。
- 回复里的出处来自检索结果的元数据（文档名、章节、页码），由前端渲染成「参考来源」，不让模型自己写书名和条款号。
- 是否超标、超多少等数字由规则代码计算，知识库只提供依据。

## 5. 入库方式

```bash
# 手动入库（全部分区；也可以 --scope company / pack:llm_deploy）
docker compose exec core python -m app.rag.ingest --scope all
# 导入演示数据时顺带入库
docker compose exec core python -m seed --with-kb
```

core 启动时如果知识库为空、并且网关里有可用的 Embedding 模型，会在后台自动入库一次；没有配置 Embedding Key 时只记日志，不影响启动。

## 6. 效果评测

- 评测集：`services/core/tests/rag/qa.yaml`，15 题。其中 12 题有标准出处（文档 + 章节），覆盖 Markdown、PDF、Excel 三种来源；3 题知识库里没有答案（年假、生日福利、停车位），用来检验拒答。
- 问题用口语化说法，不照抄原文（例如「请客户吃饭每人最多能报多少钱？」对应「客户招待按人均 150 元执行」），检验的是语义检索，不是关键词匹配。
- 指标：
  - **Top-4 命中率**：期望的文档和章节出现在前 4 条结果里（回复最多引用 4 条出处）。
  - **拒答率**：无答案的问题没有任何片段超过阈值。
- 同时对比阈值 0.4 / 0.5 / 0.6：每题只检索一次，阈值在本地过滤，不用反复调用 Embedding。

```bash
docker compose exec core python -m app.rag.evaluate --out /tmp/评测结果.md
```
